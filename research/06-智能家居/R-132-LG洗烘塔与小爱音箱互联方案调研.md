## 结论先行

**有条件能——不能直接控制，但通过 Home Assistant 中转可以实现间接联动控制。**

| 方案 | 可行性 | 难度 | 延迟 | 推荐度 |
|------|--------|------|------|--------|
| ❌ 米家App直接添加LG设备 | 不可行 | - | - | ⭐ |

| ❌ Matter直连 | 暂不可行 | - | - | ⭐⭐（未来可期） |

## 一、LG洗烘塔的智能连接方式

### 1.1 LG ThinQ 生态概述

LG WashTower 洗烘塔全线产品**内建 Wi-Fi 模块**，通过 LG 自有的 **ThinQ 平台**实现智能化：

- **配网方式**：LG ThinQ App 一键配网（支持 2.4GHz Wi-Fi）
- **App 下载渠道**（中国）：360手机助手、荣耀应用市场、OPPO软件商店、三星应用商店
- **核心功能**：
  - 远程启动/停止洗涤、烘干程序
  - 运行状态监控（剩余时间、当前程序、错误状态）
  - 推送通知（洗涤完成、故障提醒）
  - 能耗追踪（用电量统计）
  - 使用习惯分析、智能建议

> 📌 **来源**：[LG ThinQ 中国官网](https://www.lg.com/cn/lg-thinq/)

### 1.2 支持的第三方平台

LG ThinQ 官方支持的第三方语音助手/平台：

| 平台 | 支持状态 | 说明 |
|------|----------|------|
| Google Assistant | ✅ 支持 | 海外市场主要合作方 |
| Amazon Alexa | ✅ 支持 | 海外市场主要合作方 |
| **小米米家/小爱** | ❌ **无合作** | 未发现任何官方集成 |
| Apple HomeKit | ❌ 不支持 | 需通过 Homebridge 桥接 |
| Matter | ❓ 未确认 | 洗烘塔未见 Matter 认证 |

> 📌 **来源**：[LG ThinQ 中国官网](https://www.lg.com/cn/lg-thinq/)（confidence: medium）

### 1.3 LG ThinQ Connect API（开发者途径）

LG 提供了官方的 API 接入途径——**ThinQ Connect API + Personal Access Token (PAT)**：

- **PAT 生成地址**：[connect-pat.lgthinq.com](https://connect-pat.lgthinq.com)
- **PAT 权限范围**：
  - 查看所有设备及状态
  - 设备控制
  - 设备事件订阅
  - 推送通知
  - 能耗查询
- **状态**：developer.lgthinq.com 开发者文档站目前无法正常访问，但 PAT 系统仍在工作

这是 Home Assistant、Homebridge 等第三方平台接入 LG 设备的基础。

> 📌 **来源**：[connect-pat.lgthinq.com](https://connect-pat.lgthinq.com)（confidence: high）

## 二、为什么不能直接控制？

### 2.1 生态隔离

LG ThinQ 和小米米家是两个**完全独立的智能家居生态**：

- **LG ThinQ**：LG 自有平台，仅控制 LG 家电，语音助手合作方是 Google 和 Amazon
- **小米米家**：小米自有平台，主要控制米家生态链产品，语音入口是小爱音箱
- 两者之间**没有任何官方合作协议**，米家 App 无法直接添加 LG 设备，反之亦然

### 2.2 Matter 直连暂不可行

Matter 协议理论上可以打通跨品牌壁垒，但目前条件不成熟：

| 条件 | 当前状态 |
|------|----------|
| LG 洗烘塔获得 Matter 认证 | ❌ 未发现认证记录 |
| 小爱音箱支持 Matter Controller | ❓ 不明确，HA 文档列出的 Matter Controller 例子中未包含 |
| Matter 大家电品类支持 | ⚠️ Matter 1.6（2026年6月）仍聚焦优化体验，洗烘类设备认证稀少 |

**Matter Multi-fabric 的理论路径**：如果未来 LG 洗烘塔通过 Matter 认证，且小爱音箱具备 Matter Controller 功能，两者可在同一 Matter 网络中直接通信，无需云服务。但这个"如果"在当前（2026年7月）都无法成立。

> 📌 **来源**：[Matter Alpha - Matter 1.6 分析](https://www.matteralpha.com/explainer/matter-1-6-whats-new-joint-fabric-nfc)、[Home Assistant Matter 集成](https://www.home-assistant.io/integrations/matter/)（confidence: medium）

## 三、可行方案详解

### 方案 A：Home Assistant 桥接（⭐ 最佳推荐）

**原理**：以 Home Assistant（HA）为中间平台，同时接入 LG 洗烘塔和小爱音箱，通过 HA 自动化规则实现联动。

```
┌──────────────┐          ┌──────────────────┘     ┌──────────────┐
│  LG WashTower│◄────────│  Home Assistant  │◄──────│  小爱音箱     │
│  (ThinQ API) │  PAT    │  (自动化引擎)     │ Miot  │ (media_player)│
└──────────────┘  令牌   └──────────────────┘Spec   └──────────────┘
                          │
                          ▼
                    ┌───────────┐
                    │ 语音触发   │
                    │ HA 执行    │
                    │ LG 操作    │
                    └───────────┘
```

**具体步骤**：

#### Step 1：HA 接入 LG 洗烘塔

1. 在 [connect-pat.lgthinq.com](https://connect-pat.lgthinq.com) 生成 PAT 令牌
2. HA → 设置 → 设备与服务 → 添加集成 → 搜索 "LG ThinQ"
3. 输入 PAT 令牌完成配对
4. 设备类型：选择 **Washtower**（官方集成明确支持）
5. 可用实体：
   - `sensor.washtower_remaining_time`（剩余时间）
   - `sensor.washtower_course`（当前程序）
   - `binary_sensor.washtower_remote_start`（远程启动状态）
   - `button.washtower_remote_start`（远程启动按钮）
   - 能耗传感器（昨日/本月用电量）

> 📌 **来源**：[Home Assistant LG ThinQ 官方集成](https://www.home-assistant.io/integrations/lg_thinq/)（confidence: high）

#### Step 2：HA 接入小爱音箱

1. 安装 HACS（Home Assistant Community Store）
2. 通过 HACS 安装 **hass-xiaomi-miot** 插件（作者 al-one）
3. 配置小米云账号 → 自动发现并导入小爱音箱
4. 小爱音箱在 HA 中呈现为 `media_player` 实体
5. 支持功能：
   - TTS 语音播报（"洗涤已完成"）
   - 播放/暂停/音量控制
   - 执行语音命令

> 📌 **来源**：[hass-xiaomi-miot GitHub](https://github.com/al-one/hass-xiaomi-miot)（confidence: high）

#### Step 3：创建自动化联动

**示例 1：小爱语音控制启动洗烘**
```yaml
# 当小爱音箱收到"启动洗衣机"指令时
automation:
  - alias: "小爱启动LG洗烘塔"
    trigger:
      - platform: state
        entity_id: media_player.xiaomi_speaker
        to: "playing"  # 或通过自定义唤醒词检测
    condition:
      - condition: template
        value_template: "{{ '洗衣机' in states('media_player.xiaomi_speaker') }}"
    action:
      - service: button.press
        target:
          entity_id: button.washtower_remote_start
```

**示例 2：洗烘完成后小爱播报**
```yaml
automation:
  - alias: "洗烘完成通知"
    trigger:
      - platform: state
        entity_id: binary_sensor.washtower_run_state
        from: "on"
        to: "off"
    action:
      - service: media_player.play_media
        target:
          entity_id: media_player.xiaomi_speaker
        data:
          media_content_type: "music"
          media_content_id: "TTS:主人，LG洗烘塔已完成洗涤烘干"
```

**实际操作方式**（更实用）：

由于小爱音箱的语音识别结果不易直接传给 HA，**更常见的做法是反向操作**：

1. **用小爱触发的米家自动化 → 调用 HA Webhook**：
   - 在米家 App 中创建自动化，当小爱听到特定指令时，发送 HTTP 请求到 HA Webhook
   - HA Webhook 触发 LG 洗烘塔操作

2. **用 HA 内的 Xiaowo/Mi Speaker 集成直接监听**：
   - hass-xiaomi-miot 支持监听小爱音箱的对话内容
   - 当检测到关键词时触发 HA 自动化

3. **通过小爱同学技能/自定义命令**：
   - 将 HA 暴露为"虚拟设备"给米家/小爱（通过 hass-xiaomi-miot 的米家同步功能）
   - 直接对小爱说"打开洗衣机"，米家 App 中显示的虚拟洗衣机开关即触发 HA

**⚠️ 注意事项**：
- 方案依赖**互联网连接**（LG ThinQ 是云 API），断网时不可用
- API 调用频率限制：轮询间隔需 ≥300 秒，否则会被 LG 封锁 24 小时
- 推荐使用 HA 官方集成（而非社区版本），避免 API 封锁风险

> 📌 **来源**：[hass-xiaomi-miot](https://github.com/al-one/hass-xiaomi-miot)、[ha-smartthinq-sensors](https://github.com/ollo69/ha-smartthinq-sensors)（confidence: high）

### 方案 B：Homebridge 桥接

**原理**：通过 Homebridge 将 LG 洗烘塔接入 Apple HomeKit，再利用 HomeKit 自动化或 Siri 做语音控制。如果需要小爱音箱参与，仍需额外桥接。

**步骤**：
1. 安装 Homebridge
2. 安装 `homebridge-lg-thinq` 插件：`npm install -g homebridge-lg-thinq`
3. 配置 LG 账号（国家/语言）
4. WashTower 设备类型支持：状态监控 Supported，控制 Limited
5. Homebridge v2 支持 Matter 输出 → 可桥接到 Apple Home / Google Home / Alexa

**优势**：如果同时使用 Apple 生态，这条路更顺畅
**劣势**：对 LG 洗烘塔的控制能力有限（Limited），且不直接对接小爱音箱

> 📌 **来源**：[homebridge-lg-thinq](https://github.com/nVuln/homebridge-lg-thinq)、[Homebridge](https://github.com/homebridge/homebridge)（confidence: high）

---

### 方案 C：HA Matter Bridge（面向未来）

**原理**：HA 可将非 Matter 设备（如 LG 洗烘塔）通过 Matter Bridge 功能暴露为 Matter 设备。如果小爱音箱未来支持 Matter Controller，理论上可直接添加。

```
LG WashTower → HA(ThinQ集成) → HA Matter Bridge → 小爱音箱(Matter Controller)
                                                    ↑
                                              尚不支持
```

**当前状态**：HA 端已就绪（CSA 认证的 Matter Controller + Bridge），瓶颈在小爱音箱端。

> 📌 **来源**：[Home Assistant Matter](https://www.home-assistant.io/integrations/matter/)（confidence: medium）

## 四、方案对比总结

| 维度 | 方案 A (HA) | 方案 B (Homebridge) | 方案 C (Matter Bridge) |
|------|------------|--------------------|-----------------------|
| **可行性** | ✅ 现在可用 | ✅ 现在可用 | ❌ 暂不可用 |
| **控制深度** | 远程启动、状态监控、能耗 | 状态监控为主 | 取决于未来支持 |
| **小爱集成度** | ✅ 直接（hass-xiaomi-miot） | ❌ 需额外桥接 | ❓ 未来可能 |
| **语音播报** | ✅ TTS 播报洗涤完成 | 需额外配置 | 未知 |
| **技术难度** | 中等（需部署 HA） | 中等 | 低（若未来 Matter 直连） |
| **稳定性** | 高（官方集成） | 中（社区插件） | 未知 |
| **断网可用** | ❌ 依赖云 API | ❌ 依赖云 API | ✅（Matter 本地化） |

## 六、用户实操建议

### 给普通用户（零基础）

1. **最低门槛方案**：买一个 Home Assistant Green（约 ¥500）或使用旧电脑/树莓派运行 HA
2. 按方案 A 的三个步骤操作，社区有大量中文教程
3. 如果觉得 HA 太复杂，**最简单的变通**：
   - 用 LG ThinQ App 自带的推送通知功能
   - 设置小爱音箱定时提醒联动（手动触发）
   - 等待 Matter 生态成熟

### 给技术用户

1. 推荐方案 A（Home Assistant），已验证可行
2. 建议使用 Docker 部署 HA + MQTT + Node-RED 组合
3. 可探索 hass-xiaomi-miot 的"米家同步"功能，将 HA 设备反向暴露给米家 App，直接用小爱语音控制
4. 注意 API 轮询间隔设置 ≥5 分钟，避免被 LG 封锁
