## 3. 核心发现（结论先行）

1. **传输通道零新增成立**：`auto_sync_notify.py`（VPS 每 30 分钟增量 cron-auto-sync）的 MIRROR_INCLUDES 已覆盖 `baseline-paper-*`、`*_full_nav.csv`、`risk-status.json`、`engines/**`（gold 四件套）。回撤与波动率闸门所需的运行态 NAV 序列、equity 腿 NAV 均已在 VPS 镜像（实测 `baseline-paper-nav.csv` mtime 08-29 10:43）。
2. **推荐 BFF 镜像现算（R-358 nav-series 先例）作为 Phase 1**：回撤带位、20 日 realized vol 属轻量描述性计算，直接在 BFF 从镜像 CSV 现算，零 HP 改动、零 crontab 变更、实时性最好（数据 30 分钟内自动到 + 前端 120s 轮询现算）。HP 权威产物模式（R-355 hp_export_metrics 先例）列为后续可选增强，因其必须新增调度挂点（改动 crontab 或新增 timer），与零变更约束冲突。
3. **三组闸门数据可得性分层（诚实口径）**：
   - 回撤四带：**立即可用**（paper NAV 10 点，现值 1.00993 新高，drawdown=0）；
   - 波动率带：**约 2 周后满窗**（20 日窗口 vs 现 10 obs → `insufficient_obs`，与漂移 D2 前例同款呈现）；
   - 两腿相关性：**日频两腿收益序列当前不存在**——gold 腿仅有月频 `shadow_nav.csv`（2013-08 起，列 month/gold_ret/mmf_ret/nav），HP `data/` 无黄金日频数据源；equity 腿日频 NAV 止于回测 data_cut 2026-08-14。→ Phase 1 以 `insufficient_data` + 三档阈值结构呈现（PRD「无一空白」= 三元组呈现，D1/D2「暂不判带」先例已达验收），Phase 2 立项补 HP 日频产物。
4. **risk_patrol.py 与本方案无重合**：其在役产物 `risk-status.json` 覆盖退出纪律（drawdown_vs_hwm/滚动超额/Sharpe 对比），非 R-336 §4.4 组合级三闸门；本方案不复用不改它，避免动在役脚本。
5. **回撤带存在双轨口径，必须 UI 双显**：vC-0 `risk_control.drawdown_gates` 实况 = 宪章带（cut_half 25% / stop 35%，在役）+ 注释「目标 5/10/15 分级带属 Phase C 治理切换范围」。仪表以目标四带为主、宪章带标注为辅（决策点 D-3）。
6. **两腿语义澄清**：vC-0 两腿 = `equity_sleeve`（registry_ref a13_rsraw_e1f10dz，配置权重 58%）+ `hedge_sleeve_gold`（42%）；paper 当前持仓为 8 只股票纯 equity 敞口。相关性闸门衡量「配置权重下两腿收益相关性」（R-336 §7.5.4 持仓相关性语义），非当前持仓实测敞口。

### 4.3 ③传输通道设计（零 crontab 变更）

- **复用链路**：HP paper daily（16:30 在役）→ `baseline-paper-nav.csv` → `auto_sync_notify.py` 每 30 分钟增量拉取（在役 VPS cron，R-358 已验证）→ BFF 请求时现算（R-358 nav-series 同款：`fs.readFile` 镜像 → 进程内计算 → 响应）。
- **BFF 读取路径**：沿用 `config.paperNavPath`（env `PAPER_NAV_FILE` 可覆盖）；两腿参照文件新增 `equityNavPath`/`goldShadowNavPath` 两个 config 项（同模式）。

- 实时性：数据陈旧上限 ≈ 30min（sync 周期）+ 数据本身日频；前端 120s 轮询（R-342 §4.3 风控区块既定频率）。
- 可选增强（T4，需批准）：HP 侧按 R-355 模式产出权威 `risk-gates-runtime.json`（幂等导出脚本 + cron 挂点），供未来 HP 权威风控引擎对账。Phase 1 不做。

### 4.4 ④BFF risk/gates 接口扩展契约草案（risk_gates@v2，纯新增）

现有返回键（`run_date/circuit_breaker/drift/recon/pending_risks`）逐字保留；新增三块 + schema 版本号：

```jsonc
{
  "schema": "risk_gates@v2",
  "run_date": "2026-08-28",
  "portfolio_dd_gate": {
    "drawdown_pct": 0.0,            // 小数 ≤0；0=新高；4dp
    "peak_nav": 1.00993, "peak_date": "2026-08-28", "as_of": "2026-08-28",
    "band": "lt5",                  // lt5|5_10|10_15|gt15；null=数据不足
    "action": "normal",             // normal|escalated_review|cut_half|circuit_break；null 同上
    "caliber": "runtime_paper",     // 口径标注（nav-series 先例）
    "band_source": "target_5_10_15",
    "charter": { "cut_half_at": 0.25, "stop_at": 0.35, "charter_version": "1.0" }
  },
  "vol": {
    "target": 0.08, "band_pp": 0.02,
    "realized": null,               // 20 交易日滚动年化，小数 4dp；不足窗口 → null
    "window_days": 20, "obs_count": 10,
    "in_band": null,                // null=不足窗口
    "status": "insufficient_obs"    // ok | insufficient_obs | unavailable
  },
  "correlation": {
    "pair": "equity_sleeve_vs_hedge_sleeve_gold",
    "method": "pearson_rolling", "window_days": 20,
    "corr": null,                   // 小数 4dp；无日频两腿序列 → null
    "corr_prev_5d": null,           // 上升趋势判定基准
    "flag_level": null,             // 0|1|2|3（见 §4.1）；null=不足
    "flag_label": null,             // normal|watch|defensive_cut|escalated_review
    "thresholds": { "t1": 0.75, "t2": 0.85, "t3": 0.90 },
    "status": "insufficient_data",  // ok | insufficient_obs | unavailable(源缺失) | insufficient_data(序列不存在)
    "note": "gold 腿日频收益序列待 HP 产物（T3）；三档阈值结构先行展示"
  }
}
```

- **单位**：全部小数（0.08=8%，回撤 ≤0，vol/corr 年化或原值 4dp）；前端负责 ×100 显示。
- **缺失值语义（统一三态+一特例）**：`ok`（正常值）/ `insufficient_obs`（序列存在但窗口不满，如 vol 10/20）/ `unavailable`（源文件缺失，与 nav-series 降级 null 同款）/ `insufficient_data`（所需序列本生产者不存在，如相关性）。三态下数值字段=null、响应仍 200（不用 503），前端灰显+进度文案（「窗口积累中 10/20」），杜绝空白。
- **路由包装**：维持现有 `ledgerDerived(riskGatesHandler)` 不动（行为最小变化）；新字段随既有降级行为。若用户希望风控数据不受账本 503 影响，可参照 nav-series 改独立 `.catch(next)`——列为实施细节，默认不动。
- **计算实现要点**：纯 Node 内置实现（读 CSV→数组→running max/rolling std/rolling corr，O(n)），零新依赖（npm 依赖纪律与 nav-series 一致）；测试新增 ≥5 例（四带边界 0.049999/0.05/0.10/0.15、insufficient_obs、源缺失降级、charter 注入、幂等）。

1. **Phase 1（T1+T2）可在零 crontab 变更、零 HP 改动、零传输新增前提下闭环回撤四带与波动率带两闸门**，相关性闸门以 insufficient_data+阈值结构诚实呈现（PRD「无一空白」达标路径与 D1/D2 先例一致）；两约两周后 vol 窗口自然补满。
2. Phase 2（T3/T4）补两腿日频相关性真值，前置为 D-1 数据源决策；T5 HP 权威产物作为对账增强可选。
3. 全程不动：risk_patrol.py、paper_engine、registry、evolution_pipeline、auto_sync_notify.py、双侧 crontab。
4. 本方案不指定任何模型选择（用户在 GUI 自行配置）。
