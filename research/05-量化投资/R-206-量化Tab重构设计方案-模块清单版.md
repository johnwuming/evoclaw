## Tab4 回测·生命周期（战绩册 · ⭐v3版本化绑定重构 + ⭐过拟合校正可视化）

### M3.0 版本绑定器 + 四层归因链 🔴新建（⭐v3，回测Tab头部，修复核心设计缺陷）
- **定位**：修复「端到端/基线版本不绑定」缺陷。当前实现硬编码读 timing_iter4 文件——是「v4迭代快照」而非「当前生效版本战绩」，模型迭代后页面变过期数据；且基线与端到端恰好同为V2选股才对得上口径，纯靠巧合。
- **功能**：
  - **版本切换器**（Tab头部）：默认=当前生效版本（main.json → decision-log → backtest_refs），可切换查看任意历史版本
  - **四层归因链**（每层标注版本号+数据快照hash，缺层标灰）：
    ```
    ① 沪深300基准（市场本身赚不赚）
      ↓ Δ₁ = 选股alpha
    ② 选股基线（无择时，如V2_d25_n30_p10）
      ↓ Δ₂ = 择时增值
    ③ 端到端（选股×择时，同版本同快照）
      ↓ Δ₃ = 回测-模拟偏差
    ④ 模拟盘实际（paper nav）
    ```
  - **同口径纪律**（代码强制）：基线与端到端必须同一选股版本+同一数据快照hash，不匹配则对比区标红「口径失真警告」
  - **归因意义**：Δ₁证明选股跑赢基准 / Δ₂证明择时压回撤值不值 / Δ₃证明回测没骗人
- **数据契约**：decision-log 每个版本条目携带 `backtest_refs: {端到端, 基线, WF, 危机段, 数据快照hash}`（W5 runner每次迭代强制产出两腿：端到端+同口径基线）

## ⭐v4 后端版本体系（版本对象 · Registry · 流转逻辑 · 防漂移）

### 问题：现状「三张皮」

| 环节 | 版本机制 | 现状与风险 |
|---|---|---|
| 模拟盘 | ✅ model/main.json（v1.1_timing_v4_i4_q3z，选股+因子+择时完整） | paper_engine 每次运行记录 model_version，task-0272 已做对 |
| 回测 | ❌ 无 | iter系列脚本参数硬编码在脚本内，不读 main.json；回测结论与在役配置一致纯靠人工搬运，改了 main.json 回测结论静默过期 |
| 页面 | ❌ 硬编码 | 端到端API固定读 timing_iter4_metrics.csv（v4快照）；基线读一次性CSV无快照hash |
| 运行时 | ⚠️ 环境变量 | PAPER_TIMING_V4 可绕过版本记录（演练用，无自动过期） |

### 设计核心：版本对象（Versioned Model Object）

**一个「版本」= 选股 × 择时 × 因子集 × 数据快照 × 代码引用 的完整冻结组合**，任何一维变化就是新版本。

```
model/registry/
  v1.1.json   ← active（当前模拟盘在用，从 main.json 抽出）
  v1.2.json   ← candidate（回测/gate 流转中）
  ...
```

version object schema：
```json
{
  "version_id": "v1.2",
  "status": "candidate | pending | active | sota | retired",
  "created_at": "2026-08-20 21:00",
  "selection": { "strategy": "dividend_quality_smallcap", "params": {…}, "factors": ["div_yield_ttm",…] },
  "timing": { "enabled": true, "type": "i4_q3z", "params": {…} },
  "data_snapshot": { "kline_hash": "…", "financial_hash": "…", "valuation_hash": "…", "as_of": "2026-08-15" },
  "code_ref": "git commit 或 scripts/版本标记",
  "backtest_refs": {
    "endtoend": "results/bt_v1.2/endtoend.csv",
    "baseline": "results/bt_v1.2/baseline.csv",
    "walkforward": "results/bt_v1.2/wf.json",
    "segments": "results/bt_v1.2/segments.csv",
    "metrics": { "annual": 0.15, "mdd": -0.28, "sharpe": 0.43, "…" : "…" }
  },
  "gate": { "icir_is": 0.62, "icir_oos": 0.51, "max_corr": 0.58, "dsr": 0.96, "logic": "估值百分位回归中枢" },
  "provenance": { "trigger": "idea#17", "parent": "v1.1", "n_trial": 23, "report": "iteration-20260820" }
}
```

### 五个流转操作（runner 子命令，全部写 decision-log）

```
backtest  --version v1.2    读registry展开参数 → 跑两腿（端到端+同口径基线）
                             → 产物路径+指标写回 backtest_refs → 试验台账+1
evaluate  --version v1.2    读backtest_refs过五项数字门禁 → PASS则 status=pending
activate  --version v1.2    v1.2.json 内容写入 main.json（paper_engine零改动）
                             + registry状态流转 + switch_log + decision-log
rollback  --to v1.1         registry/v1.1 重新activate + decision-log（带人工确认）
override  --reason 演练      临时禁择时等，registry记录temp_override+TTL自动过期
```

### 防漂移校验（把「靠巧合一致」变成「机器保证一致」）

1. **每日校验**：paper_engine daily 启动时算 main.json 内容hash，与 registry active 版本hash 比对 → 不一致=有人手改绕过流程 → 微信告警
2. **结论新鲜度**：页面 M3.0 版本切换器读 active 的 backtest_refs，同时校验其 data_snapshot 与当前数据hash → 数据已更新而回测未重跑 → 标黄「结论基于旧数据快照」
3. **环境变量收敛**：PAPER_TIMING_V4 类 override 必须走 registry temp_override（带TTL），裸用环境变量时 paper_engine 打警告日志

### 兼容与迁移（不中断模拟盘）

- 现有 main.json 保持不动（paper_engine 继续读，模拟盘零影响）；W5 建 registry 时把当前 v1.1 抽出为第一个版本对象，activate 幂等校验 hash 一致
- 回测脚本改造：参数从「脚本内硬编码」改为「--registry v1.2.json 或 --override 单参数」（保留单参数覆盖做网格实验，但覆盖值写入试验台账）
- 基线CSV：迁移时对现有基线产物补算 data_snapshot 标记（承认历史产物无hash，如实标 unknown）

### 页面对应（前端读什么）

- M2.1 当前生效卡 ← registry[active].selection/timing + 实盘表现
- M3.0 版本切换器 ← registry 全列表 + backtest_refs
- M2.5 决策时间线 ← decision-log（每条带 version_id）
- M2.6 Pending卡 ← registry[status=pending] + gate
- M4.5 运行版本卡 ← paper summary.model_version ↔ registry active 校验结果
