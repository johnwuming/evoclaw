## 2. 数据源决策（方案 A，读时投影）

- VPS `quant-bff/live/data/` 无持仓/交易投影；`live/events/iteration-ledger-2026-08.jsonl` 仅 2 事件（Phase B）。HP 账本 16 事件（2 PhaseB + baseline/calibration/pointer + trade.fill×8 + reconciliation×2 + checkpoint）。

- **选型**：方案 A —— HP 账本一次性拉至 VPS（scp 只读，HP 零改动），BFF 从 `ctx.events` 读时投影 holdings/trades，无写路径。**理由**：改动最小（不加 HP 导出脚本、不动同步管道、不动 crontab）；BFF `ensureFresh` 已有账本变更重读机制，账本更新后视图自动跟随。
- **遗留缺口**：HP→VPS 账本持续同步（下次调仓/卖出前需就位）→ 已另登记任务中心（不动 crontab，按量化纪律需用户批准）。

## 5. 事故与修复（过程记录）

- **双前缀 bug**：fetchPortfolioTrades 初版用 `new URL(urlFor(...))` 取 pathname 后再传 getJSON（其内部再拼 API_BASE）→ 线上请求 `/quantv6/quantv6/...` 落回 index.html，页面报 `Unexpected token '<'`。修复为纯 path+查询串拼接（对齐 getJSON 契约）。教训：**getJSON(path) 的 path 必须是不含 API_BASE 的逻辑路径**，fetchEvents 用 URL 对象直取是另一条合法路径，二者不可混用。
- 测试进程挂起：新测试文件模块级 server 缺 `after(close)`，keep-alive 拖住进程不退——补上即过。
