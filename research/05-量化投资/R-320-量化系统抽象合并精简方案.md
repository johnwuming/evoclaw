## 核心发现（结论先行）

1. **60 个后端量化端点中 27 个（45%）是死端点**：14 个前端零引用（含 7 个 deprecated 桩）+ 13 个仅被"死 UI 树"消费。server.js（825KB）中约 1400+ 行死前端代码 + 对应后端 handler 可删。
2. **Dashboard 前端存在新旧两套渲染体系并存**：旧「模型/回测」页（quant-page-models/btlc，server.js L7425-7426）无任何 Tab 入口，但其完整渲染树（L11377–12836+，含版本切换器/归因链/净值图/生命周期层/报告详情）仍在；新 v5 系（v5model/v5btlc/v5hist）是其替代者。
3. **HP→VPS 有 5 条数据同步通道，其中 2 条互为重复**（push 指标 + pull 指标双写同一 metrics.db），2 条是历史残留（sync_to_vps.sh、hp_api_server /sync），实际有效 1.5 条（auto_sync_notify 镜像 + timing_matrix 专线）。
4. **HP 182 个脚本中 107 个无 cron、无内部引用、无 import**（一次性研究脚本堆积）；存在**双进化系统**（p3_3 旧自包含 vs evolution_pipeline registry 版）与**双 paper 引擎**（paper_engine A 股 vs paper_engine_gold 黄金赛道，后者为有意隔离设计）。
5. **量化动作队列双死**：入队按钮只存在于死 UI 树，且队列消费方（主 agent 心跳）在 HEARTBEAT.md v3 契约中不存在、heartbeat.sh 无相关逻辑。

## 四、合并方案（模块收敛映射）

原则：单一数据通道、单一渲染体系、死码先证据后删、HP 冻结在役件零改动。

| 现模块 | 目标模块 | 动作 |
|---|---|---|
| deprecated 桩×7、paper-旧四件、baseline/nav·yearly、endtoend | — | 删（后端 10 路由） |
| 死 UI 树（models/btlc 旧页+层加载器+报告详情+动作链） | v5 系 | 删（server.js 预计 -1400 行）；dsr/gates 若仍需展示，P1 在 v5btlc 增卡片并复用 /api/quant/dsr |
| /api/quant/btlc、e2e-curves | active/curves+f6-curves 已覆盖主场景 | 删 btlc 大路由；e2e 多版本对比若需要→并入 v5hist API |
| push+pull 双指标通道 | 保留 push（collect-metrics hp→ingest），停 pull-hp-metrics cron | 合并（VPS crontab 属低风险面，仍走用户批准） |
| sync_to_vps.sh、hp_api_server(/sync) | auto_sync_notify.py | 删/停（hp_api_server 先停服务观察 2 周） |
| factor_catalog v1/v2 并存 | v3 单一来源 | P2 数据层收敛（保留 v2 降级开关至 v3 验证） |
| p3_3 旧进化系统 | evolution_pipeline | 待确认后停 cron（唯一人工门：动 crontab 需批准） |
| HP 孤儿脚本 107 个 | ~/quant-evolve/archive/oneoff-2026Q3/ | 移档不删（保留可考古性） |
| paper_engine vs paper_engine_gold | 保持隔离，公共工具函数抽 quant_common.py | 合并代码路径不动行为 |
| 动作队列 | 若保留写操作：入口迁 v5hist/paper 活页+心跳契约补消费步骤；否则整链下线 | 待用户裁决 |
