## 一、背景

看板 v5 模型页/回测页（task-0343）此前只能展示当前 active 版本（v5h_xsub）。用户需要"版本选择器"：在看板上直接切换查看任意历史版本的指标、参数解释与回测趋势，用于横向比较迭代效果、回看已退役版本（如 SOTA 版 v2b_trr）的净值表现。前置问题：**不是全部 69 个 manifest 版本都有完整镜像文件**，盲上选择器会产生空白页/报错。故本任务分两阶段：先做数据支持评估，过闸后实现。

## 三、核心发现

### 3.1 评估矩阵（版本 × 能力，三档：✅可用 / 🟡部分 / ❌缺）

| 能力 | 支持 | 缺口 |
|---|---|---|
| 指标卡（metrics 四件套+） | ✅ 68/69 entries | ❌ v6a_def（registry-only 无回测文件） |
| 趋势图（nav 全序列，2006→2026，双窗口完整） | ✅ 68/69 | ❌ v6a_def；v4b_mve1 双条目去重后取 a5 前缀 ✅ |
| 参数解释（模板零 LLM） | ✅ 全量 44 版（registry+metrics）；🟡 部分 24 版（equiv/backtest-only，metrics 回退，择时层显示"未知"） | ❌ v6a_def |
| 基准（沪深300 日频 / 微盘等权月频） | ✅ 全版本共享 | 无版本差异，非缺口 |

主流版本（active v5h_xsub、sota v2b_trr、近三轮 a8_*/a9_* 实验）指标+趋势图 100% 支持。**结论：主流版本数据齐备 → 过闸**。

### 3.2 实现说明（增量改动，基线 server.js.bak-task0349-20260817）

**后端（3+1 处）：**
1. `quantActiveProfile(vidOverride)`：支持显式版本；manifest/registry 均无 → available:false + 回显 note（不 500）。
2. `/api/quant/active?version=`：任意历史版本档案（指标+模板解释+择时参数）。
3. `/api/quant/active/curves?version=`：历史版本 nav 双窗口 + 沪深300 + 微盘等权。
4. **新增 `/api/quant/version-options`**：全版本选项清单。字段 version_id/strategy_prefix/status/registered_at/full 窗口三指标/caps{metrics,nav,explain_full}。caps 按文件存在性判定；同 version_id 去重（v4b_mve1 保留文件齐备的 a5 前缀条）；active 置顶、其余 registered_at 倒序。

**前端（模型/回测两 tab）：**
- 共用版本选择器 `v5VersionSelHtml()`：默认=active；选项文本 `version_id (status)`；无数据版本（caps 全 false，现仅 v6a_def）禁用+后缀"（无数据）"；选中历史版显示"历史版本"徽标，回测页标题联动变"历史版本回测"。
- `_v5State.version` 持久化选择，tab 间共享、切 tab 不重置；切换即带 `?version=` 重拉 active/curves，指标卡/解释/趋势图全联动。
- 无 registry 版本由后端模板引擎自动回退 metrics（择时层"未知"），前端零特殊分支；保持零 LLM。

## 四、结论与建议

1. 版本选择器已全量落地：模型/回测两页可切换 67 个有数据版本（去重后），默认跟随 active，历史查看与现行展示互不干扰。
2. v6a_def 类 registry-only 版本保留在选项中但禁用（"（无数据）"），等其回测文件同步后 caps 自动转 true——零开发自动放开。
3. 建议（后续可选）：双版本对比视图（R-214 已预留概念）；explain_full=false 的 24 个实验版如需完整解释，可在 HP 侧补 registry。
4. 改动全部增量、经任务中心 API 与旧接口回归验证；若需回滚，基线备份 `server.js.bak-task0349-20260817` 可直接恢复。
