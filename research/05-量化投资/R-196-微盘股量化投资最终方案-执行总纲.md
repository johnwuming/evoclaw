# 第一章 执行摘要

## 1.1 一页纸方案概述

本方案是一套**面向个人投资者的 AI 驱动微盘股量化选股系统**，核心目标是利用量化因子模型在 A 股微盘股（市值<50亿）中系统性地筛选出被市场低估的标的，通过月频调仓获取超额收益。

### 核心要素

| 维度 | 方案 |
|------|------|
| **投资标的** | A股微盘股（市值<50亿，剔除ST/停牌/低流动性，约1500只） |
| **投资本金** | 10万元人民币 |
| **持仓数量** | 10只（每只约1万元） |
| **调仓频率** | 月频（每月15日调仓） |
| **业绩基准** | 中证2000指数（399303） |
| **选股模型** | LightGBM 多因子组合模型（CPU版） |
| **因子体系** | 30个基础因子（市值3+流动性5+反转4+波动3+财务8+量价7）+ RD-Agent自动进化因子 |
| **因子进化** | 半月度运行 RD-Agent，5-10轮自动因子挖掘 |
| **技术架构** | 方案D混合模式：VPS编排（OpenClaw + LLM调用）+ HP本地计算（Qlib回测） |
| **执行环境** | Conda模式（非Docker），环境变量 `MODEL_CoSTEER_env_type=conda` |
| **回测区间** | 2006-2026（20年） |
| **交易成本** | 滑点0.5% + 佣金0.025% + 印花税0.05%（卖出） |
| **预期年化** | 15-25%（基于R-186和R-188的历史回测参考） |
| **年运营成本** | 600-2400元（DeepSeek API费用） |

### 怎么赚钱

微盘股市场存在显著的**信息不对称和定价低效**。机构投资者受限于流动性约束和合规要求，难以全面覆盖1500只微盘股，导致大量标的被系统性低估。本方案通过：

1. **多因子模型捕捉定价异常**：30个因子从市值、流动性、反转、波动、财务质量、量价关系等维度全面评估每只股票，找出综合评分最高的标的
2. **LightGBM非线性建模**：相比传统等权因子合成，LightGBM能自动学习因子间的非线性交互关系，提升预测精度
3. **RD-Agent自动因子进化**：每半月自动生成并测试新因子，持续迭代模型，对抗因子衰减
4. **月频调仓控制成本**：不过度交易，每月一次调仓，平衡收益捕捉与交易成本

### 怎么执行

```
日常运行（全自动）：
  VPS上的OpenClaw → quant-compute agent → SSH到HP → Qlib回测 → 结果回传

半月度因子进化：
  RD-Agent启动 → DeepSeek生成因子假设 → CoSTEER生成因子代码
  → HP上Qlib计算 → LightGBM训练 → 回测评估 → 有效因子入库

月度调仓日（每月15日）：
  重训LightGBM → 对1500只微盘股打分 → 取前10只 → 次日开盘调仓

月末复盘：
  收益归因 → 因子衰减检查 → 策略报告
```

# 第二章 投资策略

## 2.1 为什么选微盘股

### 2.1.1 微盘股的市场定位

A股市场约5500只股票中，市值低于50亿元的微盘股约1500-2000只（随市场波动变化）。这些股票构成了中国资本市场最广泛的基础层，也是定价效率最低的领域。

**微盘股的核心特征：**

| 特征 | 描述 | 对策略的意义 |
|------|------|-------------|
| **覆盖不足** | 卖方分析师覆盖率<10% | 信息不对称 → alpha来源 |
| **机构低配** | 公募基金、外资基本不持有 | 机构行为不对冲个人投资者偏差 |
| **流动性折价** | 日均换手率低于大盘 | 流动性溢价 → 长期持有可获益 |
| **均值回归显著** | 短期超跌后反弹明显 | 反转因子IC 0.04-0.06，最稳定有效 |
| **财务信息被忽视** | 市场对微盘股财务质量定价不充分 | 财务因子（ROE、净利率等）有显著区分力 |
| **数量庞大** | ~1500只候选 | 提供足够的选股空间，分散个股风险 |

### 2.1.2 微盘股策略的学术与实证支撑

- **R-186 回测验证**：双因子（高净利润率 + 低市值）季度轮动策略在2006-2026年间实现**年化14.67%**收益，显著跑赢沪深300。该策略仅用2个因子即取得显著超额收益，30因子LightGBM组合模型预期表现更优
- **R-187 因子研究**：A股短期反转因子IC 0.04-0.06，是所有因子中最稳定的有效因子；财务质量因子在微盘股中的区分度比大盘股更强。个人投资者最适合的方向是多因子选股策略
- **R-188 Phase1验证**：量化pipeline基础设施回测实现**年化19.34%**，验证了多因子LightGBM模型在A股的有效性
- **规模溢价**：经典金融学Fama-French三因子模型中的SMB（Small Minus Big）因子在中国A股的表现尤为显著

### 2.1.3 微盘股 vs 其他选股域

| 选股域 | 股票数 | Alpha空间 | 交易成本 | 数据获取 | 适合度 |
|--------|--------|----------|---------|---------|--------|
| 沪深300 | 300 | 低（定价充分） | 低 | 容易 | ⭐⭐ |
| 中证500 | 500 | 中等 | 低 | 容易 | ⭐⭐⭐ |
| 中证1000 | 1000 | 较高 | 中等 | 容易 | ⭐⭐⭐⭐ |
| **微盘股（市值<50亿）** | **~1500** | **高** | **较高** | **需处理** | **⭐⭐⭐⭐⭐** |
| 全A股 | 5500 | 高但噪音大 | 差异大 | 困难 | ⭐⭐ |

**结论**：微盘股是个人量化投资者的最佳选股域——alpha空间大、竞争少、数量足够分散风险，同时数据获取和处理难度可控。

## 2.2 选股逻辑和因子清单

### 2.2.1 多因子选股框架

选股逻辑采用**多因子模型**框架，通过30个基础因子从六个维度全面评估每只微盘股：

```
因子体系（30个基础因子）
├── 市值因子（3个）：总市值、流通市值、市值对数
├── 流动性因子（5个）：日均换手率、Amihud illiquidity、
│                       成交额、成交额变化、零成交天数占比
├── 反转因子（4个）：5日反转、20日反转、60日反转、120日反转
├── 波动因子（3个）：20日波动率、60日波动率、特质波动率
├── 财务因子（8个）：ROE、ROA、净利率、毛利率、营收增长率、
│                    净利润增长率、资产负债率、经营现金流/总资产
├── 量价因子（7个）：量价相关、成交量比、资金流向、
│                    OBV、VR、MFI、尾盘成交占比
└── 进化因子（RD-Agent产出，动态扩展）
```

### 2.2.2 因子选择的理由——为什么不用Alpha158

根据 R-187 和 R-195 的深入分析：

| 维度 | Alpha158 | 自定义30因子 |
|------|---------|------------|
| 数据基础 | 全部基于日线OHLCV | 日线 + 财务数据 |
| 设计目标 | 面向大盘股（CSI300） | 专为微盘股设计 |
| 因子构成 | 动量40+波动30+成交量30+技术指标30+横截面28 | 市值3+流动性5+反转4+波动3+财务8+量价7 |
| 财务因子 | 无 | 8个核心财务因子 |
| 流动性因子 | 不充分 | 5个专属流动性因子 |
| 适用性 | 大盘股回测 | 微盘股回测 |

Alpha158共158个因子，全部基于日线OHLCV，不含分钟级数据。其中动量类40个、波动类30个、成交量类30个、技术指标类30个、横截面类28个。虽然数量多，但由于面向大盘股设计，在微盘股场景下需要补充财务和流动性因子。

**自定义30因子的优势：**
- 针对微盘股的流动性和财务质量问题重点设计
- 因子数量适中（30个），避免维度灾难
- 每个因子有明确的金融逻辑，可解释性强
- 为RD-Agent的因子进化提供高质量的种子集

### 2.2.3 六大因子维度详解

#### 市值因子（3个）

市值因子是微盘股策略的基础。小市值溢价是A股最持久的alpha来源之一。

| 因子 | 金融逻辑 |
|------|---------|
| 总市值（log） | 小市值公司预期收益更高（规模溢价） |
| 流通市值（log） | 流通盘更小的股票流动性溢价更显著 |
| 流通市值/总市值比 | 比值越低，锁定期越长，流动性折价越大 |

#### 流动性因子（5个）

微盘股的核心风险在于流动性不足，流动性因子既是风险度量也是收益预测因子。

| 因子 | 金融逻辑 |
|------|---------|
| 日均成交额（20日） | 成交额越低，流动性溢价越高 |
| 日均换手率（20日） | 低换手率股票倾向于更高收益 |
| Amihud非流动性 | 非流动性指标越高，预期补偿收益越大 |
| 成交额变异系数 | 成交额不稳定的股票风险更高 |
| 零成交天数占比 | 零成交天数多 → 流动性极差 → 高溢价 |

#### 反转因子（4个）

A股最稳定的有效因子族。短期反转效应在微盘股中尤为显著。

| 因子 | 金融逻辑 |
|------|---------|
| 5日收益率 | 超短期反转，投资者过度反应 |
| 20日收益率 | 短期反转，一个月内均值回归 |
| 60日收益率 | 中期反转，季度级别均值回归 |
| 120日收益率 | 半年级别反转，过滤短期噪音 |

#### 波动因子（3个）

低波动异象（Low Volatility Anomaly）：低波动股票反而表现更好。

| 因子 | 金融逻辑 |
|------|---------|
| 20日收益率标准差 | 短期波动，低波动溢价 |
| 60日收益率标准差 | 中期波动稳定性 |
| 特质波动率 | 剥离市场风险后的个股特异性风险 |

#### 财务因子（8个）

微盘股的财务质量分化极大，优质财务因子能有效区分"便宜的好公司"和"价值陷阱"。

| 因子 | 金融逻辑 |
|------|---------|
| ROE（TTM） | 高ROE = 高资本效率 → 超额收益 |
| ROA | 总资产回报率，排除杠杆影响 |
| 净利率 | 盈利能力，高净利率 = 定价权强 |
| 毛利率 | 毛利率稳定 = 商业模式可持续 |
| 营收增长率 | 成长性，高增长获得估值溢价 |
| 净利润增长率 | 盈利成长性 |
| 资产负债率 | 财务风险，过高负债 = 违约风险 |
| 经营现金流/总资产 | 现金流质量，排雷利器 |

#### 量价因子（7个）

量价关系反映了市场参与者的行为模式，在微盘股中信号噪声比更高。

| 因子 | 金融逻辑 |
|------|---------|
| 量价相关性（20日） | 量价同向 = 趋势确认；反向 = 反转信号 |
| 放量比（当日量/20日均量） | 异常放量可能预示信息驱动行情 |
| 上涨日均量/下跌日均量 | 资金方向偏好 |
| OBV（能量潮） | 累积量能，判断资金进出 |
| VR（容量比率） | 成交量相对强弱 |
| MFI（资金流量指数） | 价量结合的超买超卖指标 |
| 尾盘成交占比 | 尾盘异动可能预示次日行情 |

## 2.3 LightGBM建模说明

### 2.3.1 LightGBM的角色（用户已理解确认）

LightGBM在本方案中的角色定位非常明确：

- **不是单因子验证**——单因子IC测试用于快速筛选（IC>0.02才进入组合测试）
- **是多因子组合建模**——将30+因子作为特征输入，学习因子间的非线性交互关系
- **评估新因子的增量价值**——加入新因子后整体预测力是否提升（IC提升>0.005、夏普提升>0.1）
- **训练数据规模**：1500只微盘股 × 20年日线(2006-2026) × 30+因子 ≈ 900万行 × 30+列

### 2.3.2 为什么选LightGBM

| 模型 | CPU训练时间 | 预测力 | 可解释性 | 过拟合风险 | 适合HP？ |
|------|-----------|--------|---------|----------|---------|
| **LightGBM** | <30秒 | 强 | 特征重要性 | 中（可控） | **✅** |
| XGBoost | 1-2分钟 | 强 | 特征重要性 | 中 | ✅ |
| Random Forest | 2-5分钟 | 中 | 特征重要性 | 低 | ✅ |
| Transformer | 不可行(CPU) | 比LightGBM多1-3%年化 | 差 | 高 | ❌ |
| LSTM | 不可行(CPU) | 中 | 差 | 高 | ❌ |

**关键发现（R-195）**：Transformer比LightGBM仅多1-3%年化，不值得为它配GPU。LightGBM在CPU上对小数据集（<100万样本）反而可能比GPU更快——GPU的数据传输开销超过了计算收益。Reddit实测案例显示LightGBM 46次训练+回测，CPU 130秒 vs GPU 250秒（GPU反而慢2倍）。

### 2.3.3 模型训练参数

```yaml
# LightGBM 超参数（初始值，后续可调优）
objective: regression        # 回归任务
metric: rmse                 # 评估指标
num_leaves: 31               # 叶子数（控制复杂度）
max_depth: 5                 # 最大深度（防过拟合）
learning_rate: 0.05          # 学习率
feature_fraction: 0.8        # 特征采样比例
bagging_fraction: 0.8        # 样本采样比例
bagging_freq: 5              # 每5轮执行一次bagging
min_data_in_leaf: 20         # 叶子最小样本数
lambda_l1: 0.1               # L1正则化
lambda_l2: 0.1               # L2正则化
num_iterations: 200          # 迭代次数
early_stopping_rounds: 20    # 早停轮数
```

### 2.3.5 训练窗口长度的权衡

> ⏳ 待 task-0225 评估完成后，根据实证结果最终确定。以下为初步分析。

| 训练窗口 | 样本量 | 优势 | 风险 |
|---------|--------|------|------|
| 4年（2020-2024） | ~360万行 | 数据噪声小、制度环境一致 | 只经历1轮牛熊、泛化力弱 |
| 8年（2018-2026） | ~720万行 | 覆盖2018熊市+2020流动性牛市 | 适中 |
| 14年（2012-2026） | ~1260万行 | 覆盖多轮牛熊+2015杠杆牛 | 涨跌停规则变更（2015）、陆股通（2014）|
| **20年（2006-2026）** | **~1800万行** | **覆盖2007牛市/2008暴跌/2015杠杆牛熊/2018熊市/2024微盘股暴跌** | **股权分置改革后期、注册制（2019）、退市新规（2020）** |

**初步建议**：采用滚动训练窗口（rolling window），每次调仓时用最近 N 年数据训练，N 在 8-14 年之间根据 IC 表现动态调整。既利用长周期数据的稳定性，又避免早期制度变化带来的噪音。具体最优窗口长度待 task-0225 实证评估后确定。

## 2.4 月频调仓规则

### 2.4.1 调仓日历

```
每月15日（T日）：
  09:00  用最新数据重训LightGBM（30个基础因子+进化产出因子）
  11:00  模型对1500只微盘股打分
  15:30  收盘后确认最终排序
  16:00  按分数排序，取前10只
  17:00  生成调仓清单（对比当前持仓，计算买卖数量）

每月16日（T+1日）：
  09:25  参与开盘集合竞价，发出买卖指令
  09:30  确认成交，更新持仓记录
  10:00  检查成交情况，未成交的处理（涨停顺延/跌停延后）

每月末：
  15:30  收益归因分析（Brinson模型）
  16:00  因子衰减检查（各因子近3个月IC变化）
  17:00  生成月度策略报告
```

### 2.4.2 调仓决策规则

| 规则 | 说明 |
|------|------|
| **入选** | 模型评分排名前10的股票 |
| **替换** | 当前持仓中不在新Top-10的股票被替换 |
| **数量限制** | 单次调仓最多替换5只（控制换手率和交易成本） |
| **权重分配** | 等权配置（每只约1万元） |
| **涨停处理** | 如目标股票涨停无法买入，顺延至下一排名候选 |
| **跌停处理** | 如持仓股票跌停无法卖出，延后至次日处理 |
| **停牌处理** | 停牌股保留持仓，待复牌后按规则处理 |

### 2.4.3 调仓频率选择的理由

**为什么选月频而不是日频或周频？**

1. **交易成本控制**：每次调仓的综合交易成本约0.575%（滑点0.5%+佣金0.025%+印花税0.05%），月频年换手率约120%，年交易成本约0.7%；若周频则年换手率约500%，交易成本约2.9%，显著侵蚀alpha
2. **因子衰减周期**：反转因子和财务因子的有效周期在20-60个交易日，月频与因子有效期匹配
3. **微盘股流动性约束**：微盘股日均成交额可能仅几百万，频繁交易会严重冲击价格
4. **操作便利性**：个人投资者不需要盯盘，每月操作一次即可

## 2.5 交易成本和滑点假设

### 2.5.1 交易成本参数

| 成本项 | 费率 | 说明 |
|--------|------|------|
| **滑点** | 0.5%（单边） | 微盘股买卖价差大、流动性差，0.5%是保守估计 |
| **佣金** | 0.025%（单边） | 目前主流券商最低佣金费率 |
| **印花税** | 0.05%（卖出单边） | 仅卖出时收取 |
| **过户费** | 0.001%（双边） | 沪市股票，金额极小 |

### 2.5.2 年化成本估算

```
单次调仓成本（假设替换5只，即50%换手）：
  卖出5只：5万 × (0.5% + 0.025% + 0.05%) = 5万 × 0.575% = 287.5元
  买入5只：5万 × (0.5% + 0.025%) = 5万 × 0.525% = 262.5元
  单次合计：550元（0.55%）

年化成本（12次调仓）：
  550 × 12 = 6,600元（占10万本金的6.6%）

  → 策略年化收益必须超过6.6%才能覆盖交易成本
  → R-186策略年化14.67%、R-188策略年化19.34%，均有充足安全边际
```

### 3.2.3 数据质量处理

| 问题 | 处理方法 |
|------|---------|
| **缺失值** | 因子计算中的缺失值用前值填充或行业中位数填充 |

## 3.3 回测指标定义

### 3.3.1 收益类指标

| 指标 | 公式 | 合格标准 |
|------|------|---------|
| **年化收益率** | (期末净值)^(1/年数) - 1 | >15% |
| **累计收益率** | 期末净值 / 初始资金 - 1 | — |
| **月度胜率** | 正收益月数 / 总月数 | >55% |
| **超额收益** | 策略年化 - 基准年化 | >5% |

### 3.3.2 风险类指标

| 指标 | 公式 | 合格标准 |
|------|------|---------|
| **最大回撤** | max((peak - trough) / peak) | <25% |
| **年化波动率** | std(月收益) × √12 | <30% |
| **夏普比率** | (年化收益 - 无风险) / 年化波动 | >1.0 |
| **Calmar比率** | 年化收益 / 最大回撤 | >0.8 |
| **VaR(95%)** | 月收益的5%分位数 | >-8% |

### 3.3.3 因子评估指标

| 指标 | 公式 | 合格标准 |
|------|------|---------|
| **IC（信息系数）** | Spearman相关(因子值, 下月收益) | >0.03 |
| **ICIR** | IC均值 / IC标准差 | >0.5 |
| **IC胜率** | IC>0的月份占比 | >55% |
| **分层单调性** | 第1组与第5组收益差 | 显著（t>2） |
| **因子衰减** | 不同持仓周期下的IC变化 | 20-60日内有效 |

### 3.3.4 交易类指标

| 指标 | 公式 | 合格标准 |
|------|------|---------|
| **年换手率** | 全年买入额+卖出额 / (2×平均持仓市值) | <200% |
| **单次调仓数** | 每次调仓替换的股票数 | ≤5只 |
| **月均换手率** | 月换手率 = 月内交易额 / 持仓市值 | 40-60% |

### 5.2.3 Conda模式配置

根据 rdagent-docker-debug.md 排查：Docker基础镜像 `pytorch/pytorch:2.2.1-cuda12.1-cudnn8-runtime` 压缩后5GB+，HP无GPU下载纯浪费。Conda模式CPU PyTorch仅~200MB。

**环境变量名（关键）：**
- 正确：`MODEL_CoSTEER_env_type=conda`

# 第六章 因子进化机制

## 6.1 RD-Agent循环详解

### 6.1.1 因子进化完整流程

RD-Agent的因子进化是一个自动化的闭环系统，每一步都由LLM驱动：

```
┌──────────────────────────────────────────────────────────┐
│                RD-Agent 因子进化循环                      │
│                                                          │
│  ┌─────────┐  ┌──────────┐  ┌──────────┐  ┌─────────┐ │
│  │假设生成 │─▶│代码生成  │─▶│因子计算  │─▶│模型训练 │ │
│  │(DeepSeek)│  │(CoSTEER) │  │(Qlib)    │  │(LightGBM)│ │
│  └─────────┘  └──────────┘  └──────────┘  └────┬────┘ │
│                                                  │      │
│  ┌─────────┐  ┌──────────┐  ┌──────────┐       │      │
│  │下一轮   │◀─│入库/淘汰 │◀─│回测评估  │◀──────┘      │
│  │假设生成 │  │决策      │  │          │              │
│  └─────────┘  └──────────┘  └──────────┘              │
│                    │                                    │
│                    ▼                                    │
│           ┌───────────────┐                             │
│           │反馈生成(LLM) │                             │
│           │分析+改进建议 │                             │
│           └───────────────┘                             │
└──────────────────────────────────────────────────────────┘
```

### 6.1.2 各步骤技术细节

**步骤1：假设生成**
- LLM基于当前因子库状态生成新因子假设
- 输入：现有因子清单、近期IC表现、市场状态、知识库RAG结果
- 输出：自然语言描述的因子假设
- 模型：DeepSeek-V4，API调用1-3次

**步骤2：代码生成（CoSTEER）**
- CoSTEER将假设转化为Python代码
- 输出：符合Qlib因子接口的Python函数
- 验证：自动语法检查+小规模试运行
- 迭代：代码报错时LLM自动修复（最多5轮）

**步骤3：因子计算（Qlib）**
- 在HP Conda环境中计算因子值
- 数据源：1500只微盘股日线数据
- 输出：因子矩阵（DataFrame：日期×股票代码）

**步骤4：模型训练（LightGBM）**
- 将新因子加入现有30+因子集重训
- 比较加入前后预测力变化

**步骤5：回测评估**
- 计算单因子IC、ICIR
- 评估增量贡献（整体IC提升）
- 与现有因子做相关性分析

**步骤6：反馈生成**
- LLM分析回测结果，输出结构化反馈
- 有效则总结成功模式，无效则分析失败原因

**步骤7：入库/淘汰**
- 自动判断+research-lead Agent可override

## 6.2 进化频率和轮次

| 参数 | 值 | 说明 |
|------|-----|------|
| 进化频率 | 半月度（每月1日和15日） | 与调仓日错开 |
| 单次轮次 | 5-10轮 | 每轮=完整假设→回测→反馈 |
| 单轮耗时 | 5-12分钟 | 瓶颈在LLM API调用 |
| 单次总耗时 | 25-120分钟 | 5-10轮累计 |
| 月总轮次 | 10-20轮 | 半月度×2 |
| 月API费用 | 5-30元 | DeepSeek-V4经济模式 |

## 6.3 因子入库标准

### 6.3.1 自动入库阈值

| 评估指标 | 入库标准 | 淘汰标准 |
|---------|---------|----------|
| 单因子IC | >0.03 | <0.02 |
| ICIR | >0.5 | <0.3 |
| IC胜率 | >55% | <50% |
| 增量贡献 | 整体IC提升>0.005 | IC提升<0.001 |
| 相关性去重 | 与现有因子r<0.7 | r>0.7（冗余） |
| 经济逻辑 | LLM判断有合理金融逻辑 | 无明确逻辑或数据挖掘 |

### 6.3.2 因子生命周期管理

```
出生 → RD-Agent生成新因子
  ↓
试用期 → 前3个月密切跟踪IC表现
  ↓
正式因子 → IC稳定达标，纳入正式因子集
  ↓
监控期 → 持续跟踪IC，月度评估
  ↓
衰退期 → 连续3个月IC<0.02，标记预警
  ↓
退役 → 连续6个月IC<0.02，从因子集移除
```

## 6.4 知识库管理

### 6.4.1 因子知识库结构

| 知识类型 | 内容 | 用途 |
|---------|------|------|
| 有效因子档案 | 定义、代码、IC历史、适用场景 | 避免重复发现 |
| 无效因子档案 | 失败假设、失败原因 | 避免重复尝试 |
| 市场知识 | 微盘股特征、A股结构 | 为LLM提供背景 |
| 反馈历史 | 每轮进化的结构化反馈 | 累积研究经验 |

### 6.4.2 知识库维护

- 自动更新：每轮循环结束后自动写入
- 定期review：research-lead Agent每月审核
- Embedding服务：SiliconFlow BAAI/bge-m3，免费额度充足
- 存储位置：HP本地 `~/quant/rdagent/knowledge_base/`

# 附录A：30个基础因子完整定义和计算公式

> 所有因子均在截面上计算（每月对1500只微盘股逐只计算），因子值需做MAD去极值和Z-Score标准化。

## A.1 市值因子（3个）

### A.1.1 总市值（Log）

**定义**：公司总市值的自然对数

**公式**：`market_cap_log = log(total_shares * close_price)`

**数据需求**：总股本、收盘价 | **更新**：日频 | **方向**：负（小市值溢价）

### A.1.2 流通市值（Log）

**定义**：公司流通市值的自然对数

**公式**：`circulating_market_cap_log = log(float_shares * close_price)`

**数据需求**：流通股本、收盘价 | **更新**：日频 | **方向**：负

### A.1.3 流通市值/总市值比

**定义**：流通市值占总市值的比例

**公式**：`float_ratio = float_shares / total_shares`

**数据需求**：流通股本、总股本 | **更新**：日频 | **方向**：中性

## A.2 流动性因子（5个）

### A.2.1 日均成交额（20日）

**定义**：过去20个交易日的日均成交金额

**公式**：`avg_amount_20d = mean(amount, 20)  # amount = volume * avg_price`

**数据需求**：日成交量、成交均价 | **更新**：日频 | **方向**：负

### A.2.2 日均换手率（20日）

**定义**：过去20个交易日的日均换手率

**公式**：`avg_turnover_20d = mean(volume / float_shares, 20)`

**数据需求**：日成交量、流通股本 | **更新**：日频 | **方向**：负

### A.2.3 Amihud非流动性指标

**定义**：Amihud (2002) 非流动性度量

**公式**：`amihud_illiq = mean(abs(daily_return) / daily_amount, 20)`

**数据需求**：日收益率、日成交额 | **更新**：日频滚动 | **方向**：正

### A.2.4 成交额变异系数

**定义**：过去20日成交额的标准差/均值

**公式**：`amount_cv = std(amount, 20) / mean(amount, 20)`

**数据需求**：日成交额 | **更新**：日频滚动 | **方向**：正

### A.2.5 零成交天数占比

**定义**：过去20个交易日中零成交天数占比

**公式**：`zero_volume_ratio = count(volume == 0, 20) / 20`

**数据需求**：日成交量 | **更新**：日频滚动 | **方向**：正

## A.3 反转因子（4个）

### A.3.1 5日收益率

**定义**：过去5个交易日累计收益率

**公式**：`return_5d = close[t] / close[t-5] - 1`

**数据需求**：日收盘价 | **更新**：日频 | **方向**：负（短期反转）

### A.3.2 20日收益率

**公式**：`return_20d = close[t] / close[t-20] - 1`

**方向**：负

### A.3.3 60日收益率

**公式**：`return_60d = close[t] / close[t-60] - 1`

**方向**：负

### A.3.4 120日收益率

**公式**：`return_120d = close[t] / close[t-120] - 1`

**方向**：负

## A.4 波动因子（3个）

### A.4.1 20日收益率标准差

**定义**：过去20日日收益率标准差（年化）

**公式**：`volatility_20d = std(daily_return, 20) * sqrt(252)`

**方向**：负（低波动溢价）

### A.4.2 60日收益率标准差

**公式**：`volatility_60d = std(daily_return, 60) * sqrt(252)`

**方向**：负

### A.4.3 特质波动率

**定义**：个股收益率对市场收益率回归的残差标准差

**公式**：
```python
# CAPM回归：r_i = alpha + beta * r_market + epsilon
# 特质波动率 = std(epsilon, 60) * sqrt(252)
from sklearn.linear_model import LinearRegression
model = LinearRegression().fit(market_returns.reshape(-1,1), stock_returns)
residuals = stock_returns - model.predict(market_returns.reshape(-1,1))
idiosyncratic_vol = np.std(residuals) * np.sqrt(252)
```

**数据需求**：个股日收益率、市场指数日收益率 | **窗口**：60日 | **方向**：负

## A.5 财务因子（8个）

### A.5.1 ROE（TTM）

**定义**：滚动12个月净资产收益率

**公式**：`roe_ttm = net_profit_ttm / shareholders_equity * 100`

其中 net_profit_ttm = 最近4个季度净利润之和，shareholders_equity = 最近报告期净资产

**更新**：季频 | **方向**：正

### A.5.2 ROA

**公式**：`roa = net_profit_ttm / total_assets * 100`

**更新**：季频 | **方向**：正

### A.5.3 净利率

**公式**：`net_profit_margin = net_profit / revenue * 100`

**更新**：季频 | **方向**：正（R-186已验证有效性）

### A.5.4 毛利率

**公式**：`gross_profit_margin = (revenue - cost_of_goods_sold) / revenue * 100`

**更新**：季频 | **方向**：正

### A.5.5 营收增长率

**公式**：`revenue_growth_yoy = (revenue_current - revenue_ly) / revenue_ly * 100`

**更新**：季频 | **方向**：正

### A.5.6 净利润增长率

**公式**：`profit_growth_yoy = (np_current - np_ly) / abs(np_ly) * 100`

**更新**：季频 | **方向**：正

### A.5.7 资产负债率

**公式**：`debt_to_asset = total_liabilities / total_assets * 100`

**更新**：季频 | **方向**：负

### A.5.8 经营现金流/总资产

**定义**：经营活动现金流量净额/总资产

**公式**：`ocf_to_asset = operating_cash_flow / total_assets`

**更新**：季频 | **方向**：正

## A.6 量价因子（7个）

### A.6.1 量价相关性（20日）

**定义**：过去20日成交量变化与价格变化的Pearson相关系数

**公式**：`vp_corr = pearsonr(volume_change, price_change, 20)`

**方向**：视市场状态而定

### A.6.2 放量比

**定义**：当日成交量/过去20日平均成交量

**公式**：`volume_ratio = volume[t] / mean(volume, 20)`

**方向**：异常放量可能预示信息驱动行情

### A.6.3 上涨日均量/下跌日均量

**定义**：过去20日中上涨日的平均成交量与下跌日的平均成交量之比

**公式**：`up_down_volume_ratio = mean(volume[return>0], 20) / mean(volume[return<0], 20)`

**方向**：正（资金方向偏好）

### A.6.4 OBV（能量潮）

**定义**：On-Balance Volume，累积量能指标

**公式**：
```python
obv = []
for t in range(len(close)):
    if t == 0:
        obv.append(0)
    elif close[t] > close[t-1]:
        obv.append(obv[-1] + volume[t])
    elif close[t] < close[t-1]:
        obv.append(obv[-1] - volume[t])
    else:
        obv.append(obv[-1])
# 因子值 = OBV的20日变化率
obv_factor = (obv[t] - obv[t-20]) / abs(obv[t-20])
```

**方向**：正（资金流入=看涨信号）

### A.6.5 VR（容量比率）

**定义**：Volume Ratio，成交量相对强弱指标

**公式**：`vr = sum(volume[up_days], 26) / sum(volume[down_days], 26) * 100`

**方向**：超买区>150，超卖区<70

### A.6.6 MFI（资金流量指数）

**定义**：Money Flow Index，价量结合的超买超卖指标

**公式**：
```python
typical_price = (high + low + close) / 3
money_flow = typical_price * volume
# 14日MFI
positive_mf = sum(money_flow[tp > tp_prev], 14)
negative_mf = sum(money_flow[tp < tp_prev], 14)
mfi = 100 - 100 / (1 + positive_mf / negative_mf)
```

**方向**：MFI<20超卖（买入信号），MFI>80超买

### A.6.7 尾盘成交占比

**定义**：最后30分钟成交额占全天成交额的比例

**公式**：`tail_volume_ratio = amount_last_30min / total_daily_amount`

**数据需求**：日内分笔数据（或30分钟K线） | **方向**：尾盘异动可能预示次日行情

## B.1 一键修复脚本

以下脚本在HP上执行，修复RD-Agent Conda模式：

```bash
#!/bin/bash
# rdagent-fix-conda.sh - RD-Agent Conda模式修复脚本
set -e

echo "=== RD-Agent Conda 模式修复 ==="

# 1. 清理卡住的进程
pkill -f "rdagent fin_factor" 2>/dev/null || true
sleep 2

# 2. 修复 .env 配置
cd ~/quant/rdagent
sed -i '/MODEL_CODER_ENV_TYPE/d' .env
if ! grep -q "MODEL_CoSTEER_env_type" .env; then
    echo 'MODEL_CoSTEER_env_type=conda' >> .env
fi

# 3. 创建 rdagent4qlib conda 环境
source ~/miniconda3/bin/activate base
if ! conda env list | grep -q "rdagent4qlib"; then
    conda create -y -n rdagent4qlib python=3.10
    conda run -n rdagent4qlib pip install --upgrade pip cython
    conda run -n rdagent4qlib pip install \
      -i https://pypi.tuna.tsinghua.edu.cn/simple \
      pyqlib catboost xgboost tables
    conda run -n rdagent4qlib pip install \
      torch --index-url https://download.pytorch.org/whl/cpu
fi

# 4. 验证
conda run -n rdagent4qlib python -c \
  "import qlib, torch, lightgbm, catboost; print('All imports OK')"

# 5. 启动测试
echo "修复完成！启动命令："
echo "cd ~/quant/rdagent && rdagent fin_factor --loop-n 1 --no-checkout"
```
