## 1. P0 片面误导

### P0-1 持仓与交易视图只见微盘股票腿，黄金腿完全不可见
- **位置**：`GET /portfolios/:id/holdings`（契约 #8）、`GET /portfolios/:id/trades`（契约 #9）；前端版本页模拟盘运行态区（修复前）。
- **现状**：holdings 返回 8 只微盘股，`items` 字段仅 `[code,shares,cost_price,last_price,market_value,weight]`，**无 sleeve/腿字段**；8 只 weight 合计=1.0（**腿内归一**），用户会把股票腿内部占比误读为组合全仓配置；`total_market_value=59567` 仅为股票腿市值。黄金腿（hedge_sleeve_gold，active_paper，已入 paper 4 天）零呈现。
- **证据（实测 2026-08-30 10:25）**：
  - `/portfolios/vC-0/holdings` → `count:8, total_market_value:59567, price_basis:last_fill, source:ledger:trade.fill projection (read-time)`；`items[0] = {"code":"000848","shares":900,"cost_price":8.32,"last_price":8.32,"market_value":7488,"weight":0.125707}`。
  - `/portfolios/vC-0/trades` → 8 条全部股票代码（601600/002027/600867/300009/000848/603551/002107/300824），无腿标注。
  - 账本事件实测：16 条事件中 `trade.fill` 8 条 target 全为 `paper/vC-0#equity`——黄金腿未成交（月频首个交易日调仓，尚未到信号日），故 holdings 天然缺腿。
- **根因链（三层叠加）**：
  1. 账本 `trade.fill` payload 无 sleeve 字段，腿信息只在 target 后缀（`#equity`）；
  2. BFF `projectFills()`（app.js L261-276）按前缀 `paper/<id>#` 过滤后**丢弃 target**，两腿 fill 落同一投影（当前仅 equity 有数据，未爆发混排）；
  3. **契约 #8 items schema 本身无 sleeve 字段**（R-342 v2.0 契约总表 L417 实查）——单腿盲区已固化进接口契约。
- **分级**：P0（用户已实际被误导：「怎么让人信任看板数据是不是片面的」）。
- **状态**：**修复中——task-0575**。版本页已改「组合持仓双腿视角」（Version.jsx L137-183 动态读契约 #7 `weight_solution.weights` + `sleeves.hedge_sleeve_gold`），dist 已于 08-30 10:32 重建（产物含黄金腿渲染资产）。
- **残留动作（task-0575 之外）**：
  1. 契约 #8/#9 升版：items 增加 `sleeve` 字段（BFF 从 target 后缀解析，账本 payload 同步补字段），工作量 S；
  2. 账本写入侧：黄金腿首笔成交前确认 paper engine 事件 target 后缀规范（`#gold`/`#hedge_sleeve_gold`），避免升版后再迁移，工作量 S。

## 2. P1 不完整可补

### P1-1 /overview 端点组合主语断供：active_pv=null、sleeves=[]
- **位置**：`GET /overview`（契约 #4）；消费方为总览页三问及任何按契约接入的端。
- **现状**：实测返回 `{"nav":null,"nav_chg_1d":null,"mdd":null,"drawdown_pct":null,"active_pv":null,"sleeves":[],"last_event_ts":"...","reconciliation_ok":true}`——组合身份与两腿权重在契约字段上全部为空。
- **根因（app.js overviewHandler L146-180 实读）**：
  1. `active_pv` ← 账本投影 `composites.active_pv_id`，账本无 `promotion.executed` 事件 → null（portfolios.json note 自认「账本 promotion 链未发生」）；
  2. `sleeves` ← `active.weight_solution` 派生 → active=null 连带为空；
  3. `overview.json` 文件仅 130B：`{"nav_series":[],"note":"HP NAV 序列产物尚未输出..."}`，契约中 `sleeve_stub`（腿级 nav/mdd 数据桩）字段不存在。
- **影响**：前端总览页已自行兜底（Overview.jsx L73-79 注释自认「投影 active 指针依赖 promotion.executed，账本尚无；展示取 status 非归档的最新版本」，从 /portfolios 取 vC-0），故页面组合卡仍可渲染；但 **/overview 作为契约 #4 的组合主语出口实际不可用**，任何第二消费方（报表、告警、外部端）拿到的是空组合。
- **修复建议**：两选一——①数据侧：账本补 `promotion.executed` 事件链（走正规 promotion SOP，M）；②BFF 侧：active 指针增加快照文件兜底（portfolios.json status 权威位已有，与前端兜底逻辑对齐，S）。同时 overview.json 补 `sleeve_stub` 两腿 nav/mdd 桩位。
- **工作量**：S（BFF 兜底）／M（账本事件链）。

### P1-2 组合 NAV 两源不同步：overview.json 空置 vs 镜像 CSV 已有 11 点数据
- **位置**：`data/overview.json` vs `GET /portfolios/:id/navseries` 镜像源 `workspace-quant/results/baseline-paper-nav.csv`。
- **现状**：overview.json `nav_series=[]` → /overview 四个 NAV 系字段全 null；而同一组合的运行态 NAV 镜像 CSV 已有 2026-08-14~08-28 共 11 点（末值 1.00993），navseries 端点正常返回 `summary.nav=1.00993, mdd=-2.55%`。
- **副作用（用户可见文案打架）**：总览健康卡硬编码文案「NAV 序列待 HP 产物接入（当前无伪造数据）」（Overview.jsx L104），紧邻其下的净值区块却显示完整运行态曲线——同一页面对同一组合 NAV 一处说没有一处有。另 overview.json note「active 权重见 /api/v1/portfolios」指向裸 API，对看板用户无意义。
- **修复建议**：sync 管道把 baseline-paper-nav.csv 末段回填 overview.json（或 BFF overview 对 nav_series 空时读镜像 CSV 兜底，与 navseries 同源）；健康卡文案改为数据源感知（有运行态曲线时不再说「待接入」）；note 文案改指页面。工作量 S。
- **工作量**：S。

### P1-3 每腿运行态 NAV/回撤无 API 呈现：组合净值看不到「腿贡献」
- **位置**：`GET /portfolios/:id/navseries`（契约 #10）+ config.js L24-26。
- **现状**：navseries 仅返回组合口径（`caliber:runtime_paper`，source=baseline-paper-nav.csv）；config 已预留 `equityNavPath`（a13 全历史 NAV 镜像）与 `goldShadowNavPath`（黄金影子 NAV 镜像）两腿路径，注释明确「D-1=c 本阶段仅落配置位，相关性待 T3/T4 点亮」。两腿镜像文件实存（config 注释与 task-0565 记录一致）。
- **影响**：组合主语下用户无法回答「58% 的股票腿与 42% 的黄金腿各自净值/回撤/贡献如何」——总览只有组合一条线，腿级归因缺位。风控页有两腿**相关性**与 recon per_sleeve，但没有腿级净值曲线。
- **修复建议**：navseries 增加 `?sleeve=equity|gold` 参数（或独立 /portfolios/:id/sleeves/:id/navseries），镜像 CSV 就绪即可点亮；前端总览 NAV 区块加腿切换 tab 或风控页加两腿净值小卡。工作量 M。
- **工作量**：M。

### P1-4 总览引擎卡无组合归属/腿权重标注（P2→P1 降级）
- **位置**：总览页区块②引擎卡（Overview.jsx L152-166）；数据源 engines.json。
- **现状**：卡片渲染 sleeve_id/status/engine_id/IC/最近信号/paper 天数/数据截止；**不渲染 pv_ref（vC-0）、不渲染腿权重（58%/42%）**。数据层字段完备（engines.json 两引擎均含 `pv_ref:"vC-0"`、`sleeve_id`），属「有数据没渲染」。卡片位于 vC-0 在役版本卡之下，上下文可推断归属，但单卡截出（如通知/截图场景）不构成成分身份标注——按审计标准降级 P1。
- **修复建议**：引擎卡加两处小件：腿权重徽标（`weight_solution.weights` 已在 /portfolios/:id 返回，前端一次请求可得）+ `pv_ref` 尾注「vC-0 成分腿」。工作量 S。

### P1-5 trades 契约无 sleeve 维度：黄金腿成交后交易清单将混排
- **位置**：契约 #9 `GET /portfolios/:id/trades`。
