## 1. 调研范围与前提澄清

### 1.1 关于「AlphaEvolve（DeepSeek 开源）」的重要更正

经查证（GitHub Topics `alphaevolve`、arXiv、InfoQ/36kr 报道）：

- **AlphaEvolve** 是 **Google DeepMind** 2025 年发布的**通用进化式代码优化系统**（arXiv:2506.13131）。它以基线算法为起点，用 Gemini 生成变异候选程序，按用户定义评估函数评分、淘汰、迭代。**并非量化因子专用框架，也非 DeepSeek 出品。**
- DeepMind 官方仅公开了结果 notebook（`google-deepmind/alphaevolve_results`），**未开放运行代码**。社区开源实现为 `algorithmicsuperintelligence/openevolve`（约 6900 stars），交易移植版为 `paperswithbacktest/pwb-alphaevolve`。
- 结论：**「DeepSeek 开源的 AlphaEvolve」这一前提不成立**。本报告按「因子进化框架」的真实可比对象来盘点——即 QuantaAlpha、AlphaAgent、RD-Agent 等 LLM 驱动因子挖掘框架，并单独说明 AlphaEvolve 交易版的适用性。

### 1.2 我们现有的资产（落地约束）

| 资产 | 说明 |
| :--- | :--- |
| `microcap_data` | 5395 只（微盘股股票池） |
| `daily_pv.h5` | 1413 万行，日频价量数据（HDF5） |
| DeepSeek API | 可用（本报告方案的 LLM 引擎） |
| 硬件 | Ubuntu / 15G 内存 / 无 GPU / CPU only |

> 关键洞察：**QuantaAlpha 的因子挖掘数据格式就是 `daily_pv.h5`，回测走 qlib `cn_data`**——与我们已有的 `daily_pv.h5` 完全一致，落地兼容性极高（详见 §2.2）。

## 2. 框架逐个盘点（5 维度对比）

### 2.1 AlphaEvolve（Google DeepMind，交易移植版）

| 维度 | 评估 |
| :--- | :--- |
| **定位** | 通用进化式代码/算法优化（非量化专用）；交易版用于进化交易策略/因子逻辑 |
| **技术栈** | Backtrader 回测 + Papers-With-Backtest 数据集（Feather 缓存）+ 单个 LLM + SQLite hall-of-fame + MAP-Elites；**完全不用 qlib/qlisp** |
| **A 股支持** | 非原生（面向美股数据）；但框架标的无关，自备 A 股数据（如 pandas/我们的 h5）可适配 |
| **无 GPU 15G 内存** | ✅ 可跑（LLM 走 API + CPU 回测；本地 phi-2 2.7B 量化远小于 15G） |
| **学习成本** | 低（单 config + seed 策略文件即可启动） |

**结论**：轻量、无需 qlib、无 GPU 可跑，学习门槛低。但非 A 股原生、官方无运行代码（靠社区移植），且是「通用算法进化」而非「因子挖掘流水线」，做微盘股因子需要自己搭数据接入与评估函数。

### 2.2 QuantaAlpha（LLM 驱动的自进化因子挖掘框架）★ 重点

| 维度 | 评估 |
| :--- | :--- |
| **定位** | **LLM 自进化因子挖掘**：多样化规划 → 轨迹进化 → 假设-代码约束 → 已验证 Alpha 因子库。团队来自清华/北大/中科院/CMU/HKUST（2025.4 成立） |
| **技术栈** | **回测用 Qlib；因子挖掘用预计算 `daily_pv.h5`（HDF5）**；LLM 走 OpenAI 兼容 API（`CHAT_MODEL`/`REASONING_MODEL`，如 deepseek-v3）；React+FastAPI Web UI |
| **A 股支持** | ✅ **A 股原生**（CSI 300 主实验；官方提供 cn_data 2016–2025；零样本迁移 CSI500/SP500） |
| **无 GPU 15G 内存** | ✅ 可跑（LLM API + qlib CPU 回测；官方资源估算：小配置约 100K token / 30–60 分钟） |
| **学习成本** | 中（`run.sh "<研究方向>"` 一键运行，带 Web 界面；需配置 qlib 数据路径 + `.env`） |

**官方数据点**（arXiv:2602.07085，CSI 300 测试期 2022–2025）：
- IC 0.0472 / RankIC 0.0459；年化 4.68%；IR 0.6453；MDD 11.80%
- 支持跨市场零样本迁移（CSI500 超额约 40.3%）
- 内置质量门控（consistency / complexity / redundancy）、进化（mutation+crossover）、因子库 JSON

**与我们资产的契合点（极关键）**：
- 数据格式 `daily_pv.h5` **与我们现有 1413 万行 daily_pv.h5 完全一致**，可直接复用；
- 回测走 qlib `cn_data`——我们已有的 qlib 数据工程可直接沿用；
- 微盘股股票池可替换 instruments（CSI 用 `instruments` 目录控制，我们可自定义 5395 只池）。

### 2.3 AlphaAgent（KDD 2025，LLM 多智能体因子挖掘）

| 维度 | 评估 |
| :--- | :--- |
| **定位** | 多智能体 Alpha 因子挖掘（**Idea Agent 提出假设 → Factor Agent 构造因子 → Eval Agent 回测迭代**），对抗 Alpha 衰减 |
| **技术栈** | **基于 Qlib 回测**；OpenAI 兼容 API（`REASONING_MODEL`/`CHAT_MODEL`）；数据用 baostock 下载转 qlib 格式 + `daily_pv_all.h5` |

**结论**：与 RD-Agent 同源（官方明确「follows the implementation of RD-Agent」），但剥离了 R&D 框架的复杂性，专注因子挖掘三智能体循环。是 RD-Agent 的「精简瘦身版」，论文报告生成可行因子候选效率 +23%。**在无 GPU 15G 内存 + 免 Docker（USE_LOCAL）场景下比 RD-Agent 更易落地。**

### 2.8 Qlib 原生 AutoML / 模型集成 ★ 简单替代首选之一

| 维度 | 评估 |
| :--- | :--- |
| **定位** | Qlib 官方 `qrun` 一键自动研究工作流（YAML 配置 data→model→dataset→record 全自动，输出 IC/回测报告） |

**结论**：**Qlib 原生 workflow 无需 RD-Agent 也能跑因子挖掘**——`qrun` + Alpha158/360 特征 + LightGBM/MLP + Ensemble + rolling 回测，全部内置。这是我们「轻量自研组合」的地基（详见 §4 B 档）。注意：官方自动化重心已转向 RD-Agent，Qlib 本体更新趋缓，但核心能力稳定。

## 3. 重点对比

### 3.1 AlphaEvolve（交易版） vs RD-Agent —— 同为「进化」，谁更简单可靠？

| 维度 | AlphaEvolve（交易移植版） | RD-Agent |
| :--- | :--- | :--- |
| 回测框架 | **Backtrader**（不用 qlib） | **Qlib** |
| 定位 | 通用算法/策略进化 | 因子（fin_factor）+模型（fin_model）+联合（fin_quant）进化 |
| LLM 依赖 | 单 LLM | Chat + Embedding 双 LLM |
| 运行环境 | 无 Docker 依赖 | **需 Docker**（我们踩坑点之一） |
| A 股原生 | 否（自备数据） | ✅ 原生 |
| 学习成本 | 低 | 高 |
| 功能完整度 | 单因子/策略进化 | 因子+模型联合优化（ARR 提升 2 倍/因子减少 70%，官方） |

**结论**：AlphaEvolve 交易版**确实更简单轻量**（单配置、无 qlib、无 Docker、无 GPU），「更简单可靠」成立；但**非 A 股原生**，且官方无运行代码（靠社区移植），需要自行搭数据接入与评估函数。RD-Agent 功能更完整但依赖重、上手难——**这正是我们要替换它的原因**。

### 3.2 QuantaAlpha vs RD-Agent（同为因子进化，最直接的替代对比）

| 维度 | QuantaAlpha | RD-Agent |
| :--- | :--- | :--- |
| 数据格式 | `daily_pv.h5`（**与我们现有资产一致**） | qlib 格式 + 复杂实验管理 |
| 回测 | Qlib | Qlib |
| 复杂度 | 简化流水线（规划→进化→质量门控→因子库），`run.sh` 一键 | R&D 框架（多个 scenario、mlflow、Docker） |
| 我们踩的坑 | 无 mlflow 依赖、无 Docker 必须 | mlflow 回收失败、Docker 路径 bug、JSON schema 兼容 |
| A 股 | ✅ 原生 | ✅ 原生 |

**结论**：QuantaAlpha 在**保持 A 股原生 + qlib 回测**的同时，去掉了 RD-Agent 最繁琐的 mlflow/Docker/多 scenario 复杂度，且**数据格式与我们现有 `daily_pv.h5` 直接兼容**。是「直接替换 RD-Agent」的**最优候选**。

### 3.3 FinRL（强化学习路线）是否适合微盘股因子轮动？

**结论：不适合作为因子挖掘替换。** FinRL 经典版面向「DRL 交易/组合管理」，输入是价格/指标序列、输出是仓位/动作，**不做因子表达式挖掘**。微盘股因子轮动的核心是「选出有效因子→分层轮动」，更适合多因子 + 机器学习（LightGBM 等）流水线。FinRL 仅可作为**组合/择时执行层**的后续增强（或 FinRL-X 的 ML 选股 + DRL 择时），投入产出比低。

## 4. 三档推荐方案

### A 档：直接替换 RD-Agent 的候选

**首选：QuantaAlpha**
- ✅ **可落地点**：
  - 数据格式与我们 `daily_pv.h5`（1413 万行）**直接兼容**，回测走 qlib `cn_data`（沿用现有数据工程）；
  - A 股原生 + 微盘股可自定义 instruments 股票池；
  - 无 Docker、无 mlflow 依赖，规避了我们踩的大部分坑；
  - CPU + LLM API 即可运行，小配置约 100K token / 30–60 分钟，DeepSeek API 成本可控（比 RD-Agent 每轮 $0.028 的投入更透明可预估）；
  - 内置质量门控 + 因子库 JSON + 独立回测模块。
- ⚠️ **风险点**：项目较新（2026 论文/2025.4 团队），社区规模小于 RD-Agent；进化框架仍有 LLM 不确定性，需人工复核因子逻辑；需验证其 qlib 版本与我们现有 qlib 环境兼容（避开 segfault 等坑）。

**备选：AlphaEvolve（交易版 / OpenEvolve）**
- ✅ **可落地点**：最轻量（单配置、Backtrader、无 qlib/Docker）、无 GPU 可跑、学习门槛最低。
- ⚠️ **风险点**：非 A 股原生、官方无运行代码（社区移植版）、需自建 A 股数据接入与评估函数；适合「快速验证进化思路」而非完整因子流水线。

---

### B 档：轻量自研组合（低风险、可快速落地）

**核心：qlib 原生 workflow + 简单 LLM 因子生成**

- **第 1 步（地基，最快）**：用 **Qlib `qrun` 原生 workflow**，直接复用我们 5395 只微盘股数据，跑 **Alpha158/Alpha360 因子 + LightGBM/MLP + AverageEnsemble/DoubleEnsemble + rolling 回测**。纯 CPU、YAML 配置即可，**完全绕开 RD-Agent 的 mlflow/Docker/JSON schema 复杂度**。
- **第 2 步（LLM 因子增强）**：参照**信达证券《用 DeepSeek 优化价量因子》**（2025-03-21）的成熟方法论：以 Alpha158 为蓝本，用 DeepSeek 做「优化-验证-再迭代」因子改进与低相关新因子生成，再经 Lasso 合成。该路径实测：Alpha158 中 75% 因子 RankIC 提升、生成 5 个 ICIR>0.8 低相关新因子、中证 800 指增年化超额从 7.05%→7.92%、信息比 1.63→1.89。
- **第 3 步（可选回测层）**：用 PyBroker / backtesting.py / vectorbt 做单因子逻辑快速验证与大规模扫描，交叉检验 Qlib 结果（规避 qlib segfault 的容错）。

- ✅ **可落地点**：全部纯 CPU 可跑、无 Docker 依赖、逐步投入风险低、每一步都能独立交付；DeepSeek API 复用现有资源；直接利用我们 5395 只微盘股 + daily_pv.h5 数据。
- ⚠️ **风险点**：需要自己搭「LLM 因子生成」的 prompt 与 IC 评估闭环（工作量集中在第 2 步）；Qlib 本体更新趋缓需锁定版本；自研意味着无社区兜底，需要我们自己维护。

---

### C 档：暂不换、继续修 RD-Agent 的理由

仅在以下情况成立：
1. 已跑通 1 轮（成本 $0.028/轮 已验证），团队已投入大量时间熟悉其 R&D 框架；
2. 需要 RD-Agent 独有的**「因子 + 模型联合进化」（fin_quant）**能力（QuantaAlpha/AlphaAgent 侧重因子、不联合优化模型）；
3. 团队愿意投入人力维护其脆弱点（mlflow、Docker、JSON schema、pandas 索引）。

**综合判断**：对我们「微盘股因子轮动」的目标，RD-Agent 的「联合进化」能力价值有限，而其脆弱性代价高昂。**除非已重度依赖联合进化，否则不建议继续修。**
