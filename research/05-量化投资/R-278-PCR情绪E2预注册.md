## 三、组合形态（组合构建层调制，R-233 边界内）

**基准臂 g0_orig**：在役 a13_rsraw_e1f10dz 配置逐参复刻（BASE + E1F10DZ：raw_universe=1，ext ranksum SUM_SPECS=[(log_mv,1.0,−1),(amt20,1.0,−1),(pb_inv,0.7,+1),(roe,0.3,+1)]，e1_lambda=1.0，e1_deadzone=0.30，xsub_days=365，n_hold=20，price_cap=10，成本 v2，limit_board=on，capital_base=1e7）+ 在役择时 timing_v4_i4_q3z（ma_window=200, floor=0.30, q3z_on=True）——与 r252_run.py 逐字同源。

**候选臂（干预仅作用于调仓日的新入场集合 `added` = target_pool ∖ holdings）**：
- **降权形态（T1/T2）**：干预月调仓时，新入场（实际买入者，涨停跳过者除外）目标权重 = λ×c，留仓股 = c，c = 1/(n_ret + λ×n_add)（n_ret/n_add = 留仓/新入场只数）——组合满仓、无现金、留仓股承接权重。成本 v2 买入笔按实际目标权重计价（λ×c），卖出笔维持引擎原等权近似（w_each 族，不改）。
- **确认项否决形态（T3）**：干预月调仓时，从 `added` 中否决排名最弱（ranksum 序末位）的 k=⌈0.2×len(added)⌉ 只（added≥1 才触发，k<len(added) 则只否决 k 只；len(added)=1 → k=1 → 该月零新入场）。剩余目标池照常等权。等于把「最弱新入场」的确认项交给 PCR 贪婪态。

**实现路径**：r278_run.py 基于 a9_common.patch_engine 补丁链（r252_run.py 同构），注入块锚点为引擎源码原样区：①权重块（`w = 1.0 / len(new_pool)` / `pending_holdings` 两行）；②`added = [c for c in target_pool if c not in holdings]`（T3 注入点，否决后同步收缩 target_pool/added）；③成本 v2 买入 `order_amt = port_val * w_each`（乘 `_R278.wbuy(c)`=实际权重/等权比，非干预月恒 1.0）。引擎文件零改动。

**G0 结构保证**：λ≡1.0 且 veto≡0 时全部走原字面分支，`wbuy=1.0` 满足 IEEE x×1.0≡x → 与 g0_orig **逐位一致（max|Δnav| 须 =0.000e+00）**。G0 对拍 = 同数据同截断实现层对拍（R-253 纪律），不入台账、不计 trial。
