## 执行摘要

行业标杆（从机构平台到开源引擎）反复验证一个共同范式：**「同一套策略代码贯穿 研究→回测→模拟→实盘 四态，数据源与订单路由由框架注入，人只负责在关键检查点做决策」**。中国平台（聚宽/米筐/BigQuant/vnpy）与海外（QuantConnect LEAN / Qlib / WorldQuant BRAIN）在这一点上高度一致。

对照此范式，当前个人系统的**成熟度评估**：

| 维度 | 成熟度 | 一句话诊断 |
|---|---|---|
| 模型版本管理（main/pending/sota/switch_log） | ★★★☆ 中上 | 结构正确，缺"代码+参数+数据三版本绑定"与决策留痕 |
| 三重 gate 升级评估 | ★★★☆ 中上 | 有结构无门槛数值化，缺统计显著性/多重检验校正 |
| walk-forward | ★★☆☆ 中低 | 有 WF 意识，缺 purged/embargo、审计样本段、试验次数记录 |
| 影子并行 | ★★★☆ 中上 | 有并行账本，缺统计检验与灰度放量流程 |
| 劣化检测 | ★★☆☆ 中低 | 有检测，缺"事前写死的退出纪律"与重启流程 |
| 半月度进化规划 | ★★★★ 高配 | 个人玩家中超配，但须以"质量门禁"兜底，否则是过拟合加速器 |
| 因子库管理（72因子） | ★☆☆☆ 严重欠配 | 无生命周期状态机、无相关性去重/正交化、无 IC 台账 |
| 数据管道 | ★★☆☆ 中低 | akshare/tushare 无 Point-in-Time 保证，幸存者偏差风险高 |
| 微盘特异性风控 | ★☆☆☆ 严重欠配 | 无拥挤度/流动性/容量监控——2024 年微盘踩踏的直接教训 |
| 风险预算 | ★☆☆☆ 欠配 | 无 vol targeting / 分数Kelly / 风险分解 |
| 决策记录与实验跟踪 | ★☆☆☆ 欠配 | switch_log 有切换日志，缺 MLflow 式实验跟踪与决策日志 |
| 回测-实盘代码一致性 | ★★☆☆ 中低 | paper_engine 是"调度任务"而非"事件引擎统一抽象"，有滑点/成交假设分叉风险 |

**总体判断**：当前方案在「治理流程」上远超同类个人玩家（结构性地做对了版本、gate、WF、影子），但在「量化内核」上欠配严重——因子工程、过拟合量化校正、数据质量、微盘风控、风险预算、实验留痕。**接下来 80% 的改进优先级应放在因子台账、DSR/多重检验、Point-in-Time 数据、微盘风控、实验跟踪这五件事上，而不是继续加治理流程。**

## 维度一：行业标杆平台全景（工作流设计与信息架构）

### 1.1 行业标准做法

**QuantConnect LEAN**（海外云+开源双形态标杆）
- 核心理念：**同一引擎、同一算法代码跨 research / backtest / paper / live 四态运行**，只切换数据源与经纪商实现（20+ 券商，Paper Trading 本身就是一个"一等公民 brokerage"）。回测与实盘的一致性由架构保证，而非由人保证。
- 上线是"部署"而非"抄写"：`lean cloud live deploy --push` 一条命令上线，部署 wizard 内置通知配置、**崩溃自动重启**、初始资金/持仓继承（保证连续性）、实时数据源选择；`lean cloud status` 提供实盘唯一 ID 与状态机。
- 研究端：Jupyter 研究环境 + 高性能回测器 + 优化器 + 实盘，code-first。
- 来源：https://www.quantconnect.com/ ；https://www.lean.io/ ；https://www.quantconnect.com/docs/v2/lean-cli/live-trading/brokerages/quantconnect-paper-trading

**Microsoft Qlib**（AI 量化平台标杆，RD-Agent 母体）
- 分层工作流：Data Layer（Provider/Client → DataHandler 处理器链：标准化/填充）→ Model → Backtest → Analysis，一个 `qrun` 命令按配置文件自动跑完整流程。
- 内置 Alpha158 / Alpha360 因子库 handler；QlibRecorder 实验管理（基于 MLflow 的 MLflowExpManager，状态机 SCHEDULED→RUNNING→FINISHED/FAILED）。
- 来源：https://github.com/microsoft/qlib ；https://qlib.readthedocs.io/en/latest/component/data.html ；https://qlib.readthedocs.io/en/latest/component/recorder.html

**WorldQuant BRAIN**（众包 alpha 流水线，因子质量门禁标杆）
- 提交硬门禁（转述值，官方 criteria 页需登录）：Sharpe≥1.625（D1）/≥2.6（D0）；Returns≥6.3%/8.9%；Fitness≥1.0/1.3；Turnover∈[1%,70%]；**Self-correlation<0.7**（与自己已提交 alpha 的 PnL 相关）；prod-correlation 阈值。
- 平台自动 simulate alpha 对应组合 → 六大绩效指标打分。
- 来源：https://www.scribd.com/document/728780335/World-Quant-Brain-Alpha-Documentation ；https://zhuanlan.zhihu.com/p/1915099506304849861 ；https://gentlecactus.top/archives/132

**vnpy（VeighNa，本地开源框架标杆）**
- 三层结构：核心框架（event 事件引擎 / trader 主引擎 / gateway 约20+交易接口 / database / datafeed）+ 策略应用（cta_strategy / portfolio_strategy / algo_trading）+ 工具（cta_backtester / risk_manager / **paper_account 本地仿真** / web_trader）。
- **回测与实盘共用代码机制**：策略模板类的 `on_bar/on_tick/on_trade` 回调与 `buy/sell` 接口在回测器与实盘引擎中是同一套代码，差别只在数据来源与订单去向——撮合层被抽象。策略"类→实例"管理，parameters/variables 声明式暴露给 UI。
- **实盘启动前必须初始化**：`load_bar` 回放约 10 天历史 K 线恢复指标 + 从 `cta_strategy_data.json` 载入缓存变量（持仓、移动止损高点），保证与上次退出状态一致——这是无人值守实盘的关键工程细节。
- paper_account 基于实时盘口按到价成交撮合，委托/成交顺序与实盘一致，持仓落盘持久化。
- 来源：https://github.com/vnpy/vnpy ；https://www.vnpy.com/docs/cn/index.html ；https://www.vnpy.com/docs/cn/community/app/paper_account.html

**聚宽 / 米筐 / BigQuant（国内云平台）**
- 聚宽：研究(Notebook)→回测→模拟交易（云端托管+微信推送）→实盘（信号→QMT 执行桥接）；同一套策略 API（initialize/handle_data/order 函数族）贯穿三环境。
- 米筐：RQData(数据)→RQFactor(因子)→RQOptimizer(优化)→RQAlpha-Plus(回测)四组件按依赖分层；Mod 插件架构（sys_simulation 替换事件源/撮合）使回测与模拟共用撮合抽象；回测输出结构化 pickle 便于二次分析。
- BigQuant：数据→因子(2000+基础库+表达式引擎 big_expr)→ML模型→可视化 DAG 策略（与 Python 代码互转）→回测→模拟→实盘"无缝对接"；知识库 wiki=策略库+课程+大赛，策略卡片携带标准化绩效元数据。
- 来源：https://www.joinquant.com/ ；https://www.ricequant.com/doc/rqsdk/manual-rqsdk ；https://github.com/ricequant/rqalpha ；https://bigquant.com/ ；https://bigquant.com/wiki

**行业共同范式**：①数据与回测分层（数据层独立、可点即版本化）；②因子以"表达式/结构化"形式沉淀为可检索库；③策略面向回调接口编程、撮合层抽象 → 回测/模拟/实盘代码一致；④模拟盘是"常驻检查点"而非一次性动作；⑤实盘部署=自动重启+通知+状态恢复的工程化交付。

### 1.2 现状差距

- **paper_engine 是 3 条 cron 调度任务，不是事件驱动引擎**。这意味着回测脚本、模拟脚本、未来实盘脚本大概率是"三套接近但不完全相同的代码"，滑点/成交/状态假设可能分叉——这正是行业用"引擎统一抽象"要消灭的。
- 数据层（akshare/tushare）与策略层没有分层抽象：因子计算直接耦合在脚本里，无法像 BigQuant 表达式引擎那样沉淀、复用、检索。
- 没有"实盘状态恢复"概念：模拟盘崩溃后重新跑，是否恢复了持仓与累计状态，目前无机制保证。
- 无实盘"部署"语义：上线=跑脚本，没有通知、自动重启、状态机、唯一实例 ID 这些工程化交付物。

### 1.3 具体改进建议

1. **（最高优先级）抽事件驱动引擎层**：参考 vnpy 的 `event/engine.py`（仅 ~145 行），把策略从"脚本"重构为"回调接口 + 撮合抽象"：`on_bar/on_trade/order_*` 一套 API，回测器（历史数据推流）与模拟盘（实时数据推流）共用同一策略类。这是消除回测-模拟-实盘代码分叉的唯一根治办法。
2. **策略启动加状态恢复**：模拟盘与未来实盘启动时"历史回放 + 缓存变量恢复"（vnpy load_bar + cta_strategy_data.json 模式），记录上次持仓/累计净值/切换标记，崩溃后续跑不丢状态。
3. **实盘部署清单化**：即使暂时不上真金实盘，也把模拟盘升级为"部署式"：每条 cron 对应唯一实例 ID、崩溃自动重启、状态文件落盘、运行状态可查询（`lean cloud status` 同款语义）。
4. **因子表达式化**：把 72 因子逐步改为"表达式/算子 + 参数"的形式存储（对齐 Alpha158 与 BigQuant big_expr），为维度二的因子台账打地基。

## 维度二：因子管理标准

### 2.1 行业标准做法

**因子分类体系（Barra 风格）**
- 经济含义分类（MSCI Barra 通行）[经验值/待核实]：Beta、Momentum、Size、Non-linear Size/Mid Cap、Residual Volatility、Liquidity、Value(B/P)、Earnings Yield、Growth、Leverage。
- CNE5（2012 前后，A股）：上述风格因子 + 行业（申万/中信一级）+ 国家；CNE6（2018 后，含 CNE6S 长线 / CNE6T 交易版）：新增长期反转、Mid Cap、股息率、盈利波动等。具体清单以 MSCI Model Insight 手册为准（本次未能访问）。
- 学术侧：动量/价值/质量/低波/成长/规模六大族（Fama-French 五因子 JFE 2015；Hou-Xue-Zhang q-factor RFS 2020）。
- 已核验：Qlib Alpha158/Alpha360 按表达式组织（KMID/KLEN 价格形态 + ROLL/STD/CORR 时序统计），属工程化特征库。
- 来源：https://qlib.readthedocs.io/en/latest/ ；https://arxiv.org/abs/2009.11189

**因子生命周期状态机**（行业通行 [经验值/待核实]）
- `研发中 → 内部测试 → 模拟跟踪 → 活跃 → 观察期 → 退役`。
- 晋级条件组合：样本外 IC/ICIR 达标 + 多空逻辑成立 + 与存量因子 |ρ|<0.5~0.7 + **有经济学逻辑**（防纯数据挖掘）。
- 衰减监控：IC 滚动均值连续 N 期跌破阈值 / 因子多空收益回撤超历史极值 / 覆盖率骤降 → 观察期 → 降权或暂停加仓。
- 退役归档：保留因子定义、参数、评估快照（Qlib Recorder/MLflow 为此设计）。

**IC/ICIR/换手等评价指标**（已核验 Qlib 提供 score_ic/ICIR 分析组件；阈值 [经验值/待核实]）
- IC=因子值与下期收益横截面相关系数（Rank IC 用 Spearman）；ICIR=IC均值/IC标准差；IC 衰减=lag k 的 IC(k) 半衰期，决定调仓频率。
- 经验阈值：日频选股 |IC|>0.02~0.03 可用、>0.05 较强、>0.1 罕见需警惕过拟合；ICIR>0.3 可用、>0.5 优秀；t=|IC均值|√T/ICstd，|t|>2 显著。
- Grinold-Kahn 基本定律：IR ≈ IC×√BR（信息比≈IC×广度平方根）——《Active Portfolio Management》。
- 换手率：日频单边 20%~40% 常见（Qlib TopkDropoutStrategy 文档给出换手≈2×Drop/K 解析式，已核验）。
- 覆盖率：因子值非缺失比例，财报类因子 >80%（视股票池而定）[经验值]。

**相关性去重与正交化**（行业共识）
1. 相关性矩阵：因子两两 Rank IC 序列相关或横截面相关，|ρ|>0.6~0.7 视为高度重叠。
2. 聚类去重：对相关矩阵做层次聚类（1-|ρ| 为距离），每簇保留 ICIR 最高或逻辑最清晰者。
3. 正交化：逐步回归取残差（增量因子）；**对称正交化**（特征分解 F=UΣV′ → F(VΣV′)^(−1/2)）使因子正交且保留原始信息（A股因子工程广泛使用，石川等《因子投资：方法与实践》专章）。
4. 去重后用增量 IC / 增量 IR 评估保留价值。
5. Barra 体系：因子横截面标准化 + 风格因子对称正交保证载荷近似不相关；组合风控用暴露约束 |x_p,k−x_b,k|≤阈值（风格 ±0.5σ、市值/Beta ±0.25~0.3σ、行业 ±2%~5%）[经验值/待核实]。

### 2.2 现状差距（当前最大短板之一）

- **72 因子库无生命周期状态机**：因子只有"在库/不在库"，没有"研发中→测试→活跃→衰减→退役"流转；衰减因子不会被自动标记降权。
- **无相关性去重/正交化**：72 个因子里大概率存在高度共线簇（股息ROE选股 + 估值择时 + 量价因子互相重叠），组合层面因子暴露拥挤不可见——**RD-Agent(Q) 的核心结论恰恰是"70% 更少的正交因子达到 2× 年化收益"，多而杂是负资产**。
- **无 IC 台账**：没有为每个因子维护滚动 IC/ICIR/覆盖率/换手率/半衰期的持续监控面板，因子好坏靠"记得"而不是靠"数据"。
- **无因子评价的显著性口径**：不知道哪些因子的 IC 在统计上显著，哪些只是小样本运气。
- **无经济学逻辑门槛**：LLM 因子进化生成的因子若只过统计关、不过逻辑关，就是过拟合加速器。

### 2.3 具体改进建议

1. **建立因子注册表（factor registry）**：每个因子一行记录 `{id, 表达式/代码, 分类标签(价值/质量/动量/流动性/波动/股息...), 状态机, 首次入库日期, IC/ICIR/覆盖率/换手/半衰期 滚动指标, 上次评估日期, 相关性簇ID}`。落库到 SQLite/parquet 即可，不引重系统。
2. **上线月度因子体检**：每月对全库算 ①两两相关性矩阵→层次聚类 ②每簇只保留 ICIR 最高/逻辑最清晰者 ③输出冗余因子降权建议 ④衰减因子标记。直接对齐 Qlib `score_ic` 分析组件。
3. **因子状态机落地**：`研发中(仅回测)→测试(模拟盘影子)→活跃(参与选股)→观察(ICIR连续N期低于阈值)→退役(从库中标记,保留历史快照)`。每个状态转移都写 decision log。
4. **加经济学逻辑门槛**：LLM 进化产出的因子必须能写出一句话经济解释（如"高股息+低波动在存量市占优"），不能解释的进"统计候选区"而非"活跃区"。
5. **对称正交化治理**：对高度相关簇采用对称正交化，产出的正交因子与原因子并存评估增量 IC/IR；组合层面用暴露约束（对齐 Barra 思路）把风格暴露钉在预设范围内。

## 维度三：回测验证标准

### 3.1 行业标准做法

**过拟合防范的学术/行业标准**（已核验文献）
- **Deflated Sharpe Ratio (DSR)**（Bailey & López de Prado 2014, SSRN 2460551）：
  - 关键直觉：N 次无技能试验的期望最大 Sharpe ≈ √V[SR]×[(1−γ)Φ⁻¹(1−1/N)+γΦ⁻¹(1−1/(Ne))]，γ≈0.5772。
  - 例：日度回测、SR 方差 1/252、100 次试验 → 纯随机也能挖出年化 Sharpe≈2.5 的"假策略"；1000 次试验 → E[maxSR]≈3.26。
  - DSR = Φ[(ŜR−ŜR₀)√(T−1) / √(1−γ₃ŜR+(γ₄−1)/4·ŜR²)]，其中 ŜR₀ 用 E[maxSR] 公式计算。**DSR>0.95 才认为多重检验校正后仍有真实技能**。例：SR2.5、100试验、1250交易日、偏度−3、峰度10 → DSR≈0.90，仍有 10% 概率策略完全是假的。
  - 来源：https://papers.ssrn.com/sol3/papers.cfm?abstract_id=2460551 ；实现 https://www.marti.ai/qfin/2018/05/30/deflated-sharpe-ratio.html
- **Purged K-Fold / CPCV**：训练/验证间剔除重叠样本+embargo，防标签泄漏（重叠收益窗口）；CPCV 组合式划分给出 OOS 分布而非单点。PBO（Probability of Backtest Overfitting）：排列 IS/OOS 排名，IS 最优策略在 OOS 落底位则过拟合概率高。来源：https://papers.ssrn.com/sol3/papers.cfm?abstract_id=4686376
- **Walk-Forward（WFO）**：IS 优化→OOS 前推，滚动拼接。**关键纪律：参数超过 4~5 个时 WFO 也防不住过拟合**（clearedge.trading 等共识）；参数面要平坦（参数邻域性能平稳），不能只有孤立尖峰。来源：https://en.wikipedia.org/wiki/Walk_forward_optimization ；https://blog.quantinsti.com/walk-forward-optimization-introduction/
- **样本划分惯例**：严格时间序 train/valid/test，test 只碰一次；最终留一段"审计样本"（out-of-time audit slice）评估 regime 敏感性。

### 3.2 现状差距

- **walk-forward 有，但没有计数试验次数** → 无法计算 E[maxSR]，因此三重 gate 里"回测 Sharpe 达标"这个数字没有经过多重检验校正，**可能只是 2.5/3.26 的随机幻觉**。
- **无 purged/embargo**：若因子/模型用了滚动收益窗口（微盘短周期常见），训练与验证重叠会导致乐观偏差。
- **无审计样本段**：所有样本都进了 WF 循环，没有"最后一段谁都没碰过"的数据来验 regime 敏感性。
- **无参数平坦性检验**：gate 只问"参数下回测好不好"，不问"参数邻域是否平滑"——孤峰参数必然过拟合。
- **无"test 只碰一次"纪律**：gate 每次评估可能都复用同一段历史，等于反复测试同一个 test set，统计功效被破坏。

### 3.3 具体改进建议

1. **引入试验计数器 + DSR 校正**：在模型/因子评估系统里维护 `n_trials`（每次 gate 评估、每次因子测试、每次 LLM 进化迭代都 +1），gate 判定改为「**DSR(或至少 E[maxSR] 校正后的门槛）>0.95 才通过**」。这是性价比最高的防过拟合改造——一行计数器 + 一个公式。
2. **WF 加 embargo/purge**：标签区间（如未来 5~20 日收益）与训练集之间留 embargo（≥标签窗口），消除滚动窗口泄漏。
3. **划出审计段**：把最近一段（如 2024-06 之后）锁定为 audit slice，任何 gate 评估、任何调参都不准碰，仅用于季度性"regime 体检"。
4. **参数平坦性检验进 gate**：对候选参数做 ±10%~20% 邻域扰动，若 OOS 表现剧烈劣化 → 判定为孤峰参数，直接否决。
5. **强化 test 纪律**：同一 test 段只允许"最终确认"用一次，日常迭代只用 train/valid（或改用 CPCV 给出 OOS 分布）。
6. **记录每次回测的配置快照**（数据版本+参数+代码commit），否则无法复现，也无从统计试验次数。

## 维度四：模拟盘 / 实盘桥接

### 4.1 行业标准做法

**Paper → Live 检查点**（机构通行 [经验值/待核实]；LEAN 的 Reality Modeling 已核验）
1. 时长：模拟盘 ≥3~6 个月（低频建议覆盖一个完整财报季；高频可短）。教育界共识 30~90 天起步，达成"连续多月达到收益目标"再上。
2. 执行一致性：模拟成交 vs 回测假设的滑点差异校准（真实成交价 vs 信号价/VWAP），日均跟踪偏差收敛。
3. 信号一致性：live 与回测同代码同数据复算偏差 < 数个 bp。
4. 系统检查：断线重连、拒单率、部分成交、涨跌停/停牌处理路径演练。
5. 小资金试运行：1%~10% 目标资金先行，观察容量与冲击成本。
- LEAN 的 Reality Modeling（fill/slippage/fee/brokerage models 可插拔，Backtest→Live 同一引擎）是开源工程化范例：https://github.com/QuantConnect/Lean ；https://www.lean.io/docs/
- 上线部署标配：通知（订单事件/insight）、崩溃自动重启、初始资金/持仓显式设定或继承：https://www.quantconnect.com/docs/v2/lean-cli/live-trading/brokerages/quantconnect-paper-trading

**跟踪误差监控** [经验值/待核实]
- TE=std(组合−基准)年化。指数增强行业惯例：年化 TE 目标 3%~8%（公募合同常约束 ≤7.75%/8%）；"TE<1%" 仅用于复制型场景。
- 显著性：t=mean(active return)×√T/TE；IR=年化超额/年化TE，IR>0.5 良好、>1 优秀（Grinold-Kahn）。

**策略失效判定与退出纪律** [经验值/待核实]
- 统计判定：滚动 6~12 个月 IR 显著转负；live Sharpe < 回测 Sharpe 的 50% 且持续 2 个季度以上。
- 回撤止损：触及历史回测最大回撤 1~1.5 倍即降仓；触及净值 −15%~−20%（或波动率×k）停止策略，复盘后经决策重启。
- 因果判定：区分"统计性回撤"与"逻辑失效"（拥挤度、政策、市场结构证据）。
- **关键原则：退出纪律必须在事前写死在风控章程，不允许事后放宽。**

**Pre-trade 风控清单**（券商/机构通行 [经验值/待核实]）
单票 ≤5%~10%、单行业 ≤20%~30%；单日交易量 ≤ 该票 ADV 的 5%~15%（大资金 1%~3%）；价格偏离拒单（乌龙指防 ±3%）；涨跌停/ST/退市名单拦截；T+1 制度；保证金/额度检查；事前 Barra 暴露/TE/VaR 超限阻断。

### 4.2 现状差距

- paper_engine 有模拟盘，但**没有定义"模拟→实盘"的检查点清单**：模拟盘跑多久、跟踪误差多少、滑点偏差多少算"可上实盘"，目前无量化标准。
- **无执行一致性对比**：没有把模拟成交价 vs 信号价/VWAP 的偏差记录下来校准滑点假设。
- **无跟踪误差/预期差异的显著性监控**：微盘策略以中证2000/微盘指数为基准的话，超额/基准偏离的统计量没有监控面板。
- **无事前写死的退出纪律**：劣化检测有，但"连续 N 月跑输基准即降仓/停策略""最大回撤 X% 即熔断"没有在风控章程里写死；而行业共识是**退出纪律必须事前定义、不允许事后放宽**。
- **无 pre-trade 清单**：若未来上实盘，集中度/流动性/ADV/涨跌停拦截全部缺失；而微盘恰恰是集中度和流动性风险最高的品种。

### 4.3 具体改进建议

1. **写一份"模拟→实盘检查点"风控章程**（一次性的文档+脚本）：
   - 门槛①：模拟盘连续运行 ≥6 个月或覆盖 ≥1 个完整财报季；
   - 门槛②：模拟成交 vs 回测假设的日均滑点偏差 ≤ 预设阈值（先用历史数据标定）；
   - 门槛③：信号复算偏差 < 数个 bp；
   - 门槛④：模拟盘经历至少一次 ≥5% 回撤且系统表现符合预期（未崩溃、状态恢复正常）；
   - 门槛⑤：小资金（≤10% 目标资金）试运行 ≥1 个月。
2. **加跟踪误差监控日报**：输出 组合超额 vs 基准 的滚动 IR、TE、t 统计量；阈值：滚动 IR 连续 3 个月转负 → 触发劣化 review。
3. **把退出纪律代码化**（替代"人工观察"）：`max_drawdown_trigger`（历史回测最大回撤×1.5 → 强制降仓 50%；净值 −20% → 熔断停止）＋ `underperform_months`（连续 N 月跑输基准 → 进入观察/降权），全部事前配置，禁止事后放宽。
4. **补 pre-trade 模块**（即使暂时不实盘也先把逻辑写好）：单票权重上限、ADV 比例限制、涨跌停/ST/退市名单拦截、T+1 校验——这些对微盘策略尤其生死攸关。

## 维度五：自动化进化闭环

### 5.1 行业标准做法

**因子挖掘自动化谱系**（已核验）
- 闭式风险模型（Fama-French）→ GP 符号回归（gplearn：https://gplearn.readthedocs.io/en/stable/）→ RL 因子组合优化（AlphaGen, KDD 2023：https://github.com/ICT-FinD-Lab/alphagen）→ LLM 生成式挖掘（RD-Agent / AlphaForge：https://arxiv.org/abs/2406.18394）。
- **协同性（synergy）评估**：AlphaGen 不只优化单因子 IC，而是优化"因子集"组合后的表现——因子层面的目标函数，对冗余因子天然降权。
- **质量门禁怎么设**：
  - **WorldQuant BRAIN 流水线**（提交门禁 + 相关性去重硬阈值）：Sharpe/Returns/Fitness/Turnover 门槛 + self-correlation<0.7 + prod-correlation。例外规则：高相关但 Sharpe 显著更高可破例。→ **每次提交都是"硬门禁+去重"流水线，不是"跑通了就行"**。
  - **RD-Agent(Q)**（NeurIPS 2025, arXiv:2505.15155）：五单元闭环 Specification→Synthesis→Implementation(Co-STEER 代码生成)→Validation(真实回测)→Analysis(统一指标+多臂老虎机调度)；维护 SOTA 集合，假设生成同时参考最近反馈与 SOTA 实验；**成功→增加复杂度/范围，失败→结构性调整或引入新变量**；每个假设/实现/结果持久存储，形成知识累积。关键实证：成本 <$10 达到 2× 年化收益、因子减少 70%+。
  - **评价指标体系**：BRAIN 六大指标（Sharpe/Returns/Drawdown/Turnover/Fitness/Margin）+ 相关性门禁；RD-Agent 的统一指标评估 + 多臂老虎机自适应选方向。

### 5.2 现状差距

- **半月度进化规划是"超配"**（个人玩家中罕见），但若质量门禁不硬，进化越快=过拟合越快。**LLM 因子进化的产出必须过与手动因子相同的硬门禁（维度二的 IC 台账 + 维度三的 DSR/去重），否则就是自动化地制造垃圾因子。**
- **缺"协同性"评估**：当前只评估单因子/单模型，没有在"因子集组合"层面评估进化产出的增量价值——可能与存量 72 因子高度共线，白白增加维度。
- **缺硬门禁的数值化**：BRAIN 有明确的 Sharpe/Fitness/self-corr 数字门槛；我们目前没有给 LLM 进化产出定义可自动执行的通过/拒绝阈值。
- **缺知识累积结构**：RD-Agent 把每轮假设+实现+结果持久存储成知识森林；我们若只有"因子进来/出去"，没有进化历史的知识沉淀，进化就是无记忆的随机游走。

### 5.3 具体改进建议

1. **给进化闭环定义"数字门禁"**（对齐 BRAIN）：
   - 新因子/新模型必须同时满足：①IS 全样本 ICIR 达标（用维度二阈值）②OOS（WF 段）ICIR 达标且不显著劣于 IS ③与存量因子最高 |ρ|<0.7（超过则要求 Sharpe 显著更高才破例）④DSR>0.95 ⑤一句话经济学逻辑。
   - 任一不满足 → 拒绝并记录原因，不进入 pending。
2. **加"组合增量"评估**：每个进化候选先在"现有因子组合"里做增量 IC/增量 IR 检验（去掉它组合 IC 是否下降），只有增量为正才保留——直接落实 AlphaGen/RD-Agent 的协同性思想。
3. **进化历史建"知识库"**：每轮进化记录 `{假设, 实现代码, 指标结果, 通过/拒绝, 原因}`，允许后续进化引用历史结果（RD-Agent 知识森林的轻量版），避免重复挖已否掉的因子。
4. **控制进化节奏与预算**：半月度规划保留，但每次进化批次设"试验预算"（如单批次最多 N 个候选、总试验次数计入 DSR 的 n_trials）——让进化加速器在统计校正的护栏内运行。

## 维度六：风险管理与回退机制

### 6.1 行业标准做法

**版本回退与灰度/蓝绿** [经验值/待核实——工程实践类比]
- 版本管理三件套：**代码版本(git) + 配置/参数版本(实验跟踪) + 数据快照版本**，三者绑定一个 release tag 才能复现。
- 上线节奏：shadow（影子）→ 小资金灰度(1%~10%) → 逐步放量(10%→30%→100%)，每步设通过指标（TE/执行成本/错误率）。
- 回退：保留上一版本热备（权重+参数+数据管道），一键切回；**回退触发条件事前定义**。
- 蓝绿变体：新旧策略各占独立子账户，切换即资金划转，避免同账户混仓。

**Shadow trading / A/B 并行统计检验** [通行做法/待核实]
- 设计：新策略产生信号但不下单（或极小单），与生产策略同一时点、同一数据、同一执行假设并行记账（parallel book），至少覆盖一个策略周期 + 不同市况。
- 对比检验：①配对日度超额收益差的 t 检验；②双样本 Sharpe 比较（Jobson-Korkie 或 bootstrap，Ledoit-Wolf 修正）；③White's Reality Check / SPA 防多重检验偏差（Sullivan, Timmermann & White 1999）；④灰度期 ≥1~3 个月 + "执行成本不恶化"检验。
- 已核验：Qlib Online Serving（OnlineManager/OnlineStrategy/Updater）提供实盘前影子验证：https://qlib.readthedocs.io/en/latest/component/online.html

**风险预算** [经验值/待核实；Qlib risk_analysis 已核验]
- 波动率目标：仓位 ∝ 目标波动/预测波动，EWMA(λ≈0.94) 预测；学术支持 Moreira & Muir "Volatility-Managed Portfolios"（JF 2017）。
- Kelly：f* = μ/σ²，行业几乎一律用**分数 Kelly（0.25~0.5 倍）**应对估计误差与厚尾（Thorp SSRN #906854）。
- 风险预算分解：组合主动风险贡献分解（因子/资产/策略），单因子风险预算 ≤10%~20%；危机期相关性趋 1 自动缩总杠杆。

### 6.2 现状差距

- **模型版本管理（main/pending/sota/switch_log）结构正确**，但缺"配置/参数版本 + 数据快照版本"绑定——切回旧模型时若数据管道已改，则无法真正复现旧版本行为。
- **影子并行有，但无统计检验**：影子与主版本并行跑了，却没有"配对 t 检验 / Jobson-Korkie / SPA"来决定切换与否，gate 可能靠"目测净值曲线"。
- **无灰度放量流程**：升级是"切换"而非"影子→小资金→放量→全量"的阶梯，缺少在小资金阶段发现问题的安全垫。
- **无风险预算层**：没有 vol targeting、没有分数 Kelly、没有因子/策略级风险预算分解——微盘策略波动高，无目标波动通道意味着行情过热时仓位不自动收缩。

### 6.3 具体改进建议

1. **版本三件套绑定**：每次 switch_log 记录 `{模型commit, 参数/配置hash, 数据快照hash/日期, gate 指标, 切换原因}`；回退操作要求"数据快照可回放"。
2. **影子并行加统计检验脚本**：每半月进化评估时自动对影子 vs 主版本跑：①配对日度超额差 t 检验 ②Jobson-Korkie Sharpe 比较（bootstrap 版）③记录 SP 检验结果。只有统计显著且方向正确才允许 switch_log 的升级记录。
3. **升级改为灰度阶梯**：pending→影子(只记账)→小资金灰度(≤10%资金,≥1个月)→逐步放量→全量；每级设通过指标（TE 不劣化、执行成本不恶化、错误率）。
4. **引入风险预算模块**：
   - 波动率目标：仓位 = 目标波动(如年化 12%~15% 通道) / EWMA 预测波动，波动超通道自动降杠杆；
   - 分数 Kelly：按 f*=0.25×μ/σ² 给总仓位上限；
   - 单因子/单模型风险预算 ≤ 组合 10%~20%，超标自动降权。
5. **回退触发条件代码化**：灰度组/全量 live 指标劣于旧版本对照组超过阈值（如滚动 IR 转负、执行成本恶化）→ 自动回退到上一版本（保留热备）。

## 维度七：决策记录与可解释性

### 7.1 行业标准做法

**实验跟踪（MLflow / W&B / Qlib Recorder）**（已核验）
- 行业标准 = 实验跟踪三件套：**参数/配置版本化 + 指标与 artifact 记录 + 可复现运行（代码+数据+环境快照）**。
- MLflow：开源自托管、轻量；W&B：托管协作、可视化强；Qlib 内置 MLflowExpManager（experiment→recorder 两级，状态机 SCHEDULED/RUNNING/FINISHED/FAILED）。
- 来源：https://qlib.readthedocs.io/en/latest/component/recorder.html ；https://wandb.ai/site/experiment-tracking/ ；https://github.com/Tussar98/quant-ml-research
- **可复现铁律**：同一实验必须能复现——代码版本、参数、数据快照、随机种子、依赖环境缺一不可。
- **决策日志（decision log）**：每次策略上下线/换版本/因子晋级退役，记录"谁、何时、依据什么指标、预期影响、备选方案、回退条件"，类似 ADR（Architecture Decision Record）实践。
- **可解释性**：RD-Agent(Q) 强调生成"可验证的因子/模型代码"而非黑箱信号，以降低幻觉；BRAIN 的 alpha 是公式表达式，天然可解释。

### 7.2 现状差距

- **switch_log 有切换日志，但没有实验跟踪**：每次回测/因子测试的结果、参数、数据版本没有系统记录，无法回答"这个 IC 是在哪个数据版本上算的"。
- **无决策记录规范**：升级/降级 switch_log 里只有"做了什么"，缺"为什么、依据什么指标、预期影响、回退条件"。
- **无可复现保障**：数据管道（akshare/tushare）每次拉取可能不同（数据修订、前视修复），无数据快照意味着历史实验结果天然不可复现。
- **LLM 进化产出的因子缺可解释性门槛**（见维度二）：黑箱因子无法审计、无法在失效时判断是"统计波动"还是"逻辑失效"。

### 7.3 具体改进建议

1. **接轻量实验跟踪**：用 MLflow（或自建 ~200 行 SQLite 记录器，API 对齐 mlflow）：每次回测自动记录 `{run_id, code_commit, params, data_snapshot_hash, 指标集(IC/ICIR/Sharpe/DD/TE/DSR/n_trials), artifacts路径}`。
2. **数据快照化**：数据管道加"快照日期+内容hash"，因子/模型评估必须绑定数据快照；回测缓存 key 用 `code_commit+params_hash+data_hash`，保证可复现与可缓存。
3. **决策日志模板化**：把 switch_log 升级为结构化决策记录 `{决策ID, 日期, 类型(升级/降级/因子晋级/退役/熔断), 触发指标, 预期影响, 备选方案, 回退条件, 责任人}`。进化评估的每次通过/拒绝也写入。
4. **可解释性进 gate**：LLM 进化产出必须附公式表达式 + 一句话经济解释（对齐 BRAIN alpha 表达式 + RD-Agent 可验证代码），黑箱候选不通过。

## 维度八：个人量化的现实约束

### 8.1 行业标准 vs 个人现实（个人 vs 机构差距）

| 维度 | 机构 | 个人 | 影响 |
|---|---|---|---|
| 数据 | 逐笔行情、Tick级、Point-in-Time 数据库、另类数据 | akshare/tushare 日频/分钟，无 PIT 保证，财务数据修订不可追溯 | 因子前视/幸存者偏差风险最高 |
| 算力 | GPU 集群、量化研究平台、专用回测器 | 单机 CPU | 回测深度、参数寻优广度受限 → 更易过拟合 |
| 数据质量治理 | 专职数据团队、交叉校验、PIT 重放 | 无校验机制 | 脏数据直接进因子 |
| 风控 | 专职风控、事前/事中/事后三层、熔断机制 | 一人身兼研究员+风控 | 无独立制衡，退出纪律易被"再等等"突破 |
| 执行 | 算法执行(TWAP/VWAP)、做市合作、低滑点 | QMT/手动，滑点大 | 回测收益≠实盘收益的差距更大 |
| 容量 | 万亿规模管理，容量研究专业 | 个人资金容量小（反而是优势：可做机构进不去的微盘） | 微盘拥挤度要自己盯 |
| 治理 | 投委会、合规、审计 | 一人决策 | 决策偏差无制衡 |

**个人系统的核心矛盾**：机构用"工程冗余"对抗"市场随机性"，个人没有冗余，所以**必须把行业标准里"靠人盯"的部分改成"靠自动化护栏"**——这正是本报告所有建议的主线。

**微盘策略特异性风险（与我们直接相关，已核验事件）**
- 2024-01~02 A股量化危机：微盘踩踏，中证1000单月约 −18.7%、中证2000 约 −21.0%，微盘股无量跌停、流动性危机，量化产品 5~10 年一遇回撤。诱因=策略拥挤 + 雪球敲入 + DMA 杠杆平仓 + 微盘天然流动性薄。
- 来源：https://zhuanlan.zhihu.com/p/682434497 ；https://www.chnfund.com/article/AR2024022515282476361206 ；https://m.36kr.com/p/2656817840980232 ；http://m.eeo.com.cn/2024/0224/639051.shtml ；https://pdf.dfcfw.com/pdf/H3_AP202404121630186501_1.pdf
- **启示：微盘/小市值策略必须有拥挤度监控、流动性压力测试、容量估算、快速降仓熔断。**

### 8.2 现状差距

- 数据层无 PIT 校验、无幸存者偏差处理：akshare/tushare 退市股/ST 覆盖不全，回测容易"只看到活下来的股票"。
- 财务数据前视风险：股息/ROE 用"财报期"还是"实际披露日"，若用错就是前视偏差。
- 无拥挤度/流动性监控：这是微盘策略 2024 年那类踩踏的直接护栏缺失。
- 无独立制衡：研究员=风控=执行，退出纪律尤其脆弱。

### 8.3 具体改进建议

1. **数据管道加三关**：①退市股/ST 纳入回测（至少标记，避免幸存者偏差）②财报字段用"披露日"而非"报告期"（财务 PIT）③数据修订留痕（拉取快照 hash）。
2. **加微盘拥挤度指标**：监控 ①微盘/小市值指数换手率与成交占比 ②组合持仓在微盘区间的占比 ③小市值相对中证800 的超额滚动衰减 ④雪球敲入风险代理指标（中证500/1000 距离敲入线）。任一异常 → 自动降仓。
3. **流动性压力测试**：回测里加"最坏 5 个交易日只能以 N% 冲击成本成交"的压力场景，看策略是否崩。
4. **容量估算**：按"单日交易量 ≤ 该票 ADV 的 5%~15%"倒推策略容量上限，避免回测里能买、实盘里买不进。
5. **独立风控视角**：即使一人系统，也把"策略开发"和"风控章程"分离——风控阈值（维度四的退出纪律、维度六的风险预算）作为独立配置文件，开发过程不得随手改动；改动需记录 decision log（维度七），形成"准独立制衡"。

## 当前方案成熟度评估：超配与欠配清单

### 超配（做得比行业平均好的部分，应保持）
1. **半月度进化规划**：个人玩家中罕见地把"进化"当流程管理而非随缘，接近机构的研究-开发节奏。✔ 但必须以质量门禁兜底（见欠配④），否则超配变负资产。
2. **三重 gate 升级评估**：多数个人玩家根本没有结构化升级评估，我们有了。✔ 缺的是数值化门槛（DSR/统计显著性）。
3. **模型版本管理（main/pending/sota/switch_log）**：结构正确，对齐"main/SOTA 集合"思想（RD-Agent 也维护 SOTA）。✔ 缺三版本绑定与决策留痕。
4. **walk-forward 意识**：比"一段式回测"先进。✔ 缺 purged/embargo/审计段/试验计数。

### 欠配（行业有标准而我们缺的，按优先级排序）
1. **因子工程**（维度二）：72 因子无生命周期、无去重/正交化、无 IC 台账——**当前最大的结构性短板**。
2. **过拟合量化校正**（维度三）：无 DSR/E[maxSR]、无试验计数、无审计段——gate 的"Sharpe 达标"未校正多重检验，可能是在认可随机幻觉。
3. **数据质量与 PIT**（维度八）：无幸存者偏差处理、无披露日 vs 报告期区分、无数据快照——所有下游结论的地基。
4. **微盘特异性风控**（维度八）：无拥挤度/流动性/容量/熔断——2024 微盘踩踏的直接教训，与我们策略高度相关。
5. **实验跟踪与决策留痕**（维度七）：无 MLflow 式实验记录、决策日志未模板化——不可复现=不可审计。
6. **风险预算**（维度六）：无 vol targeting / 分数 Kelly / 风险分解——仓位控制靠感觉。
7. **回测-实盘一致性架构**（维度一/四）：paper_engine 是 cron 脚本不是事件引擎——模拟与未来实盘必然分叉。
8. **退出纪律的事前写死**（维度四）：劣化检测有，但"连续N月跑输→降仓""回撤X%→熔断"未代码化。

**一句话总结**：治理流程（版本/gate/WF/影子/进化节奏）是超配的"骨架"，量化内核（因子台账/统计校正/数据质量/风控预算/留痕）是欠配的"血肉"。当前优先级应全部押注欠配项，而非继续堆治理流程。

## 个人量化容易踩的坑清单（12 条，按杀伤力排序）

1. **幸存者偏差**：回测只用当前还在交易的股票，退市/ST/暴跌股被剔除 → 收益虚高。用带退市股的历史池。[来源：https://zhuanlan.zhihu.com/p/639158715 ；https://bigquant.com/wiki/doc/sT15bVfKHl]
2. **未来函数/前视偏差**（含最阴险的"选择偏差型"）：用了回测当天才知道的数据（财报报告期而非披露日、复权因子后移、指数成分股当前名单回测过去）。[https://zhuanlan.zhihu.com/p/1997690714780348805]
3. **多重检验不自知**：反复试参数/试因子直到"某组回测好看"，试验次数无记录 → 纯随机也能挖出 Sharpe 2.5~3.3 的假策略（E[maxSR]）。[https://www.marti.ai/qfin/2018/05/30/deflated-sharpe-ratio.html]
4. **成本低估**：佣金/印花税/滑点/冲击成本算得太乐观，微盘尤其严重（涨跌停买不进卖不出）。[https://zhuanlan.zhihu.com/p/2014098758099559459]
5. **参数孤峰**：只在某个精确参数点回测漂亮，邻域一扰动就崩——必须做参数平坦性检验。[https://blog.quantinsti.com/walk-forward-optimization-introduction/]
6. **微盘流动性/容量误判**：回测能买，实盘买不进；2024 年 1 月微盘踩踏（中证2000 单月 −21%）就是流动性危机的教科书案例。[https://zhuanlan.zhihu.com/p/682434497]
7. **策略拥挤不监控**：自己赚的超额其实是"跟风同一个拥挤因子"，同行一撤就崩——微盘拥挤度必须监控。[https://www.chnfund.com/article/AR2024022515282476361206]
8. **无事前写死的退出纪律**：劣化时总想"再等等"，结果 20% 回撤变 50%。退出阈值必须在风控章程里事前定义、禁止事后放宽。
9. **回测与实盘代码/假设分叉**：回测脚本、模拟脚本、实盘脚本三套代码各差一点 → 实盘表现系统性偏离。必须用事件引擎统一抽象。[https://github.com/vnpy/vnpy]
10. **财务数据前视**：用财报期而非披露日 → 高估因子收益。必须 PIT（Point-in-Time）化处理。
11. **无数据快照/不可复现**：数据一更新，旧回测结果全变，无法复盘"当初到底测了什么"。
12. **一人身兼研究员+风控无制衡**：决策偏差无人纠正。解法：风控阈值独立配置文件+改动留痕，模拟"准独立制衡"。
