## 三、核心发现（结论先行）

1. **看板已是一个事实上的「引擎A单机版」**：六子Tab（数据/因子/模型/回测/模拟实盘·灰度/迭代历史）全部围绕在役 a13_rsraw_e1f10dz 的单 registry 版本线组织；`/api/quant/registry` 无 engine 概念，多 active 并存时按 created_at 取最新（L2410，task-0392 注释）——这是单引擎假设的代码残留，也是多引擎化的第一个真实缺口。
2. **层2 中央风控现在零组件**：现有 risk-status/crowding 是引擎A的监控指标，挂在模拟实盘页，不是组合级风控。战略配置器/再平衡带宽/组合回撤门在代码中完全不存在，属净新增（等触发）。
3. **两整个隐藏页成僵尸 UI**：控制面页（quant-page-models，含决策时间线/Pending确认/想法池/试验台账/操作队列，M2.5-M2.9）与四层归因链页（quant-page-btlc，含版本绑定器/归因链/危机段/walk-forward/报告库/验证层，M3.0-M3.7）代码完整、取数正常，但被移出 Tab 序列（无 qseg 按钮、不在 _V5_TABS，L6854/6855 vs L8897），UI 不可达。判「迭代（复活）」——多引擎恰恰需要引擎级控制面与归因链。
4. **13 条路由可删（3 组，代码级证据）**：7 条 quantDeprecated 弃用桩、4 条连字符旧 paper 路由（被斜杠版替代、零前端引用）、2 条 baseline/nav+yearly（零引用）；另有 endtoend（392 行逻辑）零调用者，判「待确认」。
5. **影子观察「有后端、无前台」**：lifecycle 端点已实现 shadowWatch 扫双 registry 的 gate.shadow_watch（L2614-2624，task-0383/R-248 机制），但唯一前台消费点在隐藏页 H2 → 引擎 B 影子通道的后端地基已在，缺的是可达 UI。

## 四、目标架构（四层 N 引擎通用框架，用户已确认定调）

- **层0 共享数据基础设施**：采集/PIT 对齐/快照/退市处理等，服务所有引擎，不隶属任何引擎。
- **层1 引擎层（可插拔同类组件，数量 N）**：每个引擎同构 = 信号/选股逻辑 + 择时与回撤内化（引擎自己消化择时，顶层不做方向择时）+ 独立 NAV + 独立 registry 版本线 + 影子观察通道。现有实例：引擎 A = 在役 a13_rsraw_e1f10dz（微盘选股）。在途候选：引擎 B = 全 A 行业轮动（E1 达线 R-255，k=1 行业动量 Top5，待 E2）。未来 C/D 按同一接入标准扩展。
- **层2 中央风控层（独立横切，不属于任何引擎，尤其不是 B 的配套）**：战略配置器（N 引擎权重，按风险贡献定）+ 再平衡带宽（偏离机械拉回，不追近期表现）+ 组合级回撤门（保险性质）。哑层、无方向观点。单引擎时期 w=100% 无事可做，第二引擎上线才激活——这是时序巧合，不是架构归属。
- **层3 组合与呈现层**：组合净值 = Σ wi×NAVi（N 通用聚合，引擎数可变）+ 各引擎独立呈现。
- **引擎上线路径**：双 NAV 影子观察先行（参照 a12_s2_reb 影子机制 R-248），影子期满再谈真金分配；信号层合并（真复合模型）远期，不在本报告范围。
