## 0. 破什么、立什么（方法论定位）

| 破（推倒的个人历史包袱） | 立（标准替代物） | 评审依据 |
|---|---|---|
| 私有术语体系（A腿/gold腿/GM1-15/F6/F7/R-xxx 进代码命名） | 标准术语七层架构 + GLOSSARY.md 唯一对照表 | 评审缺点1「术语代号强耦合」 |
| 状态机隐式存于可变 JSON（composites/engines/registry） | append-only event_log，JSON 降级为重放投影缓存 | 评审缺点2「未做事件溯源」 |
| 门禁靠口径描述、无逐层数字 | 分层毕业阈值表（研究→影子→paper→canary，全数字） | 评审缺点3「未量化=主观放行」 |
| 回测引擎基于旧脚本打补丁、正确性未审计 | 回测正确性审计清单（六项），不通过=迁移硬阻塞 | 评审缺点4「错误回测上越严格越危险」 |
| 只有归档、无退役规则 | 客观退役规则 + 影子 4 维漂移监控 | 评审缺点5/6 |
| 零常驻=零兜底 | 断路器 + checkpoint + 仓位对账三件套 | 评审缺点7 |
| 组合权重靠口径拍板（F6/F7 二选一） | 组合构建层（可插拔求解器：等波动率→风险预算/ERC，不用 MVO） | 23:39 增补建议 |

保留不破：组合作为一等版本对象、一切变更走同一条流水线、成绩单=回测成绩+逐条门禁原因、三方对账、双层门禁（组件级管「单拎够不够格」/组合级管「拼起来行不行」）、个人单机约束（不引入消息队列/多服务，事件账本=本地 JSONL）。

### 1.2 逐层职责 / 接口 / 可插拔点

**① Data Layer 数据服务层**
- 职责：行情/财务/公告数据的唯一权威出口。四口径在此冻结并强制下发：PIT 对齐（NOTICE_DATE 细则，R-328）、qfq 前复权唯一口径（R-330 F4）、退市股全包含、涨跌停可交易掩码（Mask-First，R-333 实证 300862 一字板不可成交）、成本模型（R-333 实测三情景：记账 4.0bp / 可实现中间态 11.5bp/边 / 小微上限 15.7bp/边）。
- 输入：原始数据源（东财公告、腾讯 qfq、akshare）。
- 输出契约：`bar(symbol, date, ohlqfq_adj, tradable_mask, pit_fields...)`；任何上层拿到的数据必须已带掩码和复权，禁止上层自行 join 财务（000001 滞后 371 天反例即违反此契约的后果）。
- 可插拔点：**新资产类别**（可转债 R-332、利率债 ETF R-331、QDII R-330）= 新增一个 data adapter，注册进四口径校验清单即可，不动其他层。

**② Alpha Layer 因子/信号层**
- 职责：因子挖掘、验证、产出标准化 signal。现有 evolution_pipeline（registry 版，g1-g6 组件门禁）、辩论代理（R-334 吸收的双子代理）、Mask-First/ICIR+HMM（落 M5 择时）都归这层。
- 输入：Data Layer 契约数据。
- 输出契约：`signal(sleeve_id, date, positions, ic_series, turnover_estimate)`。
- 可插拔点：**新因子/新引擎** = 新 signal producer，注册进组件门禁（g1-g6），产物只是 portfolio_version 的一个候选组件指针。**新调度器**（半月/周/cron 变更）= Alpha Layer 内部实现细节，对下游不可见。

**③ Backtest Layer 回测层**
- 职责：组件回测 + 组合回测（composite_backtest），输出结构化成绩单（组合层指标 + 逐 episode 差分 + 声明区 + 门禁逐条通过/不通过）。**审计后可信是本层存在前提**（第 5 节）。
- 输入：signal + portfolio_version 配置（经组合构建层解析为权重）。
- 输出契约：`backtest_report(portfolio_version_id, metrics, gate_results[], assumptions[], md5_anchor)`。
- 可插拔点：**第二裁判**（qlib qrun 双轨，R-334 表②）= 独立回测实现注册进交叉验证清单，双窗 e2e diff 达阈值前不替换在役；F6/F7 口径 = composite_backtest 的两个口径插件（口径1=ddc 释放补 gold；口径2=50/50 打底+REDUCE 0.25/0.75）。

**④ Portfolio Construction Layer 组合构建层（新增）**
- 职责：给定风险预算，求解各 sleeve 权重。**与⑤解耦的铁律：portfolio_version 存「配置」（sleeve 指针/风控参数/求解器选型+参数），本层输出「权重求解结果」——配置与求解分离，禁止在 portfolio_version 上直接加 model_weights 字段**（否则配置与求解耦合，sleeve 增多后失控）。构建两步显式化（v1.2，A2）：①求解前候选先过 Data Layer `tradable_mask` 过滤（可预测≠可交易；Mask-First 数据侧已备，R-333 实证）；②`weight_solution` 输出前做后验检查——权重取整、最小交易单位、现金残留，超容差即告警留档并重解。
- 演进分阶段：第一阶段=等波动率（equal-volatility，两三腿时最稳健）；第二阶段=风险预算/ERC（协方差用 Ledoit-Wolf 收缩估计）；**晋升路径明确不用 MVO**（对收益预测误差极敏感，易过拟合集中；v1.2 用户 2026-08-28 10:00 裁决：Phase B 增设带约束 MVO 对比跑批——跑批不启用、仅对照留档，P3 复盘用实际跑批数据重议，见 §8 Phase B 动作 7）。
- 输入：各 sleeve 的滚动波动率/协方差（Data Layer 历史窗 + Backtest 层 sleeve 净值曲线）、风险预算参数。
- 输出契约：`weight_solution(portfolio_version_id, solve_date, weights{}, solver_meta{type, params, cov_estimator, cov_estimator_rationale, convergence_status, random_seed, diagnostics, fallback_triggered, fallback_reason})`——求解结果本身也追加进 event_log，可重放。
- fallback 与留痕约定（v1.2，A3+A4）：`cov_estimator_rationale` 记录协方差选型对比结论（Phase B 校准期 LW vs 样本 vs EWMA 各跑一遍留档，判定指标=OOS 波动率预测误差 + 协方差条件数）；`fallback_triggered:bool` + `fallback_reason:enum`（fb_* 前缀枚举）；**fallback 生效必产一条 weight.solved 事件（payload reasons 含 fb_* 与触发场景：定时/RC 偏离/兜底），杜绝静默回退**。
- 可插拔点：**新求解器** = 注册式 solver（equal_vol / risk_parity / ERC / 未来 HRP），portfolio_version 里只存 solver_id+params。P2/P3 的约束体系、分层风险预算、HRP、体制切换=演进方向，本方案不现在做。

**⑤ Portfolio Layer 组合层**
- 职责：portfolio_version 一等对象（继承 R-335 vC-x.y 全部设计，重命名）：`{portfolio_version_id, sleeves{}, risk_control{drawdown_gates, vol_target, backfill_rule}, per_sleeve_risk_cap?, solver_ref, parent_version, status, gate_report, paper_entered_at, paper_duration}`。
  - **层级纪律（v1.1）**：`risk_control` 只存**组合级**约束；单腿级风控参数（含 ddc）下沉到各 sleeve 自己的版本对象；`per_sleeve_risk_cap`（可选）= 组合层对单腿设的风控上限封顶（语义：只封顶、不下指令，不替代 sleeve 自身风控）。
  - `backfill_rule` 显式定义（v1.1）：**禁止回填含未来信息的统计量**（如用未来均值/未来波动率做 zscore、用全样本分位数做标准化）；其校验纳入正确性/无前视门禁范围（与 §5.1 A1 前视偏差审计同口径，gate spec 落库时归 G-B 类 backtest-correctness 组）。
  - `paper_entered_at` = 进入 paper 时刻（原 paper_since 改名）；`paper_duration` = 已处 paper 状态的时长（由 paper_entered_at 自动推导，G-L1 时长计算依据）。
  - schema 扩充（v1.2，A1）：`sleeves{}` 每条组件指针附 `code_hash + data_cut`（model manifest 最小集）；新增 `capital_policy{gross_limit, net_limit}`；`solver_ref` 扩为 `solver_id + params + tolerances + fallback`；constraints（bounds/turnover/sector）按 §1.2④ 既定口径留 P2 演进，不进 v1.2。
  - data_cut 硬断言（v1.2，A1）：**data_cut ≤ min(所有输入数据源最大时间戳)**，校验器强制执行，违反即 `config.invalid`（绝对阻塞，不允许降级放行）。
- promotion 状态机（v1.1 补反向迁移）：正向串行晋升 `candidate → backtested → gated → shadow → approved → paper → canary → live`，终态 `archived / retired`；反向降级：`live → shadow`（运行时 4 维漂移超标自动降级，触发=§7.2 任一维连续 2 期超带）、`live → gated`（严重问题回滚到门禁重审，触发=reconciliation.failed / 断路器熔断 / 审计不合格）。**降级事件同样追加 event_log（promotion.downgraded），不允许人工直改 JSON 破坏 append-only。**
- 输入：weight_solution + backtest_report。
- 输出契约：portfolio_version 对象 + 一张成绩单（用户唯一消费物：过了没、为什么没过）。
- 可插拔点：**新 sleeve** = components 加一条指针 + 权重求解器自动扩维（第三腿利率债 R-331 就这么进）。

**⑥ Execution Layer 执行层**
- 职责：paper → canary → live **串行三段**执行（模拟盘 → 小资金实盘 → 全额；canary 为 live 前必经段，非二选一）、调仓、撮合假设声明（收盘竞价可成交=当前假设，R-333 已证其对佣金计费方式敏感）、checkpoint 快照。
- 输入：portfolio_version（live 指针）+ 权重。
- 输出契约：`execution_report(date, fills, slippage_actual, nav, checkpoint_ref)`。
- 可插拔点：**paper→live 切换** = 本层唯一人工门（用户批准）；canary 档 = 小资金实盘灰度（串行第二段），当前未启用，启用后为 live 前必经；启用时须先定义期限与失效自动降级条件（v1.2，A4）。

**⑦ Risk Layer 风控层**
- 职责（裁决顺序三段式（v1.1），优先级高 → 低：**熔断硬上限 > 组合级裁决 > 单腿级裁决**；任一熔断触发——单腿 ddc>20% 或组合回撤>15%——立即停，硬上限不可被任何层级覆盖）：
  - 组合级：回撤分级闸门（<5% 正常 / 5–10% 提级审查 / 10–15% 降仓×0.5 / >15% 熔断）+ 波动率目标化（参数位：target_vol 初版 8%，再平衡带 ±2pp）+ 断路器 + 退役规则；
  - sleeve 级：ddc（现 ddc_th20_rd50_rc5，受控净值回撤 ≤−20% → ×0.5，回补 −5%，T 判定 T+1 生效）保留不动，参数下沉存 sleeve 版本对象自身（§1.2⑤），组合层仅以 per_sleeve_risk_cap 设上限。
  - 再平衡协调协议：sleeve 内部重大调仓后，组合层进入**冷却期（1 个完整调仓周期）**，期间组合级不因该 sleeve 风险贡献（RC）变化反向加仓——防「减仓→RC 骤降→被反向加仓」横跳震荡。
- 可插拔点：新风控规则 = event_log 里的 risk.* 事件类型扩展，不动状态机。

**横切 Iteration Ledger**
- append-only JSONL 事件账本（第 3 节）：每层每次状态变更追加事件；composites.json/engines.json/registry 全部降级为「重放投影缓存」。个人单机约束保留：本地文件，无消息队列、无常驻服务。

### 3.3 事件格式与重放（单机版）

每行一个 JSON 对象：`{"ts": "2026-08-27T23:30:00+08:00", "actor": "evolution_pipeline|user|risk_layer", "event_type": "gate.evaluated", "target": "vC-2.0", "payload": {...}}`。写前做 `flock` 互斥（cron 与手动操作并发安全）；每行写完即 fsync；按月滚动文件（`iteration-ledger-2026-08.jsonl`）。

重放伪代码：

```python
def replay(ledger_files) -> State:
    state = State()                      # 空状态
    for line in chain(*ledger_files):    # 按时间序
        ev = json.loads(line)
        state.apply(ev)                  # 幂等 apply：version.created 建对象、
    return state                         # promotion.executed 移指针、risk.action 记录
# 投影缓存 = replay 结果 dump 回 registry/engines/composites JSON
# 校验：每次重放后对投影做 sha256，与缓存文件头记录比对，不一致即 reconciliation.failed
```

不引入消息队列/数据库：个人单机下 JSONL+flock 足够，结构上已满足「事件不可改、状态可重放、历史可审计」三要件。

### 3.6 paper 运行数据供给管道（v1.5 新增）

解决「模拟盘净值/持仓/买卖/手续费散装在 CSV/JSON、事件账本不镜像」的缺口（用户 2026-08-29 10:27 提出，核实成立）。镜像语义：**权威数据文件仍为 HP paper_engine 的 results/trades.csv、results/paper-nav.csv、results/paper-state.json，事件账本只是 append-only 镜像，引擎写路径零改动**。

- **镜像写入时机**：paper_engine 收盘日更（NAV）与调仓完成后，由钩子把新增行翻译为 `trade.fill` / `nav.daily` 追加进 iteration-ledger；钩子失败**不阻塞引擎主流程**（只留镜像缺口标记），由对账兜底补齐——引擎不改写路径，保证 Phase C 分钟级切换可行性（§8）
- **对账兜底**：每次调仓后 + 每日日终，镜像事件与权威 CSV/JSON 逐字段比对，不一致即 `reconciliation.failed`（复用 §3.3 投影 sha256 对账链路，R-353 §4 已演练）

## 6. 安全兜底三件套（P0）

评审缺点 7：零常驻服务=无灾备，实盘一旦自动下单缺兜底很危险。三件套全部落在 Execution Layer 与 Risk Layer，事件全部进 event_log。

### 6.1 断路器（circuit_breaker）

| 触发条件 | 初版阈值 | 动作 |
|---|---|---|
| 单日亏损 | ≥ 2.0% NAV | 当日停止开新仓（已持仓不动） |
| 组合回撤 | 进入 10–15% 带 | 降仓 ×0.5（分级闸门联动） |
| 组合回撤 | > 15% | 熔断：停新仓 + 提级审查 + 用户通知 |
| 报错率 | 连续 2 次调仓执行失败 或 日频任务连续 3 日失败 | 暂停自动流程转人工 |
| 数据陈旧 | NAV mark 停摆 ≥2 交易日（R-333 已发现 6 日停摆先例） | 冻结一切自动决策 |

恢复规则：断路器动作只能人工复位（promotion.approved 同级人工门），自动恢复禁止。

### 6.2 状态 checkpoint

每次调仓执行完成后写快照：`{date, positions, cash, nav, portfolio_version_ref, ledger_offset, md5}`。恢复 = 最近 checkpoint + 重放 checkpoint.ledger_offset 之后的 event_log。验证：恢复重建的持仓 vs paper 账本 diff=0。

### 6.3 仓位三方对账（three_way_reconciliation）

paper 账本 vs 引擎持仓 vs portfolio_version 定义，三方核对：
- 频率：每次调仓日强制 + 每周例行；
- 容忍度：单 sleeve 权重差 ≤1pp、现金差 ≤0.5% NAV、持仓标的集合完全一致；
- 超限动作：写 `reconciliation.failed` 事件（含差异明细）+ 冻结开新仓 + 用户通知。现有 paper 一致性徽标（P0/quantConsistDot）升级为本对账的前端呈现。

## 7.5 组合构建层与裁决协议增补（用户 2026-08-27 23:47 验收清单逐项落地）

> 来源：`work/acceptance-checklist-r336.md`（用户提供）。**第 7.5.1 与 7.5.3 为验收硬门**（schema/状态机级），已显式写入本协议；第 7.5.2 与 7.5.4 并入修正阶段（Phase B 影子双轨期实现）。

### 7.5.1 vC/PV 版本承诺边界（验收硬门）

- **版本承诺「结构」与「风险预算」，不承诺具体权重数值**。
- **不升版本（运行时重算即可）**：①协方差矩阵用新一期数据刷新 → 权重变；②单腿内部风控调整导致风险贡献变化 → 组合层重算。两者都不产生新版本号、不走门禁。
- **必须升版本（走完整流水线 + 成绩单）**：①换求解器（等波动率 → 风险预算/ERC）；②改风险预算分配（如 A腿 45%→40%）；③加/减模型（sleeve 增减）；④改相关性筛查阈值（0.75）。
- **口诀：「预算怎么分」进版本，「分出来的数」运行时算。**
- 与 §1.2④「配置与求解分离」衔接：portfolio_version 只存结构/预算/求解器选型+参数，weight_solution 永远运行时产出并追加进 event_log。

### 7.5.2 运行时重算双触发 + 交易成本闸门

- **重算触发显式化（双触发）**：默认「定时（每周一开盘前）+ 偏离触发（某腿风险贡献偏离目标 > 阈值）」；任一触发即重算 weight_solution。偏离阈值量化口径（v1.4）：具体数值在 Phase B 影子期标定后冻结（建议锚 5pp 起议）；标定完成前用保守缺省 5pp 并标注「标定前缺省值」。
- **再平衡过交易成本闸门**：预期风险下降收益 > 换手 × 双边成本 才执行。
- **硬规则**：单次再平衡换手率上限 ≤ 20% 净值。

### 7.5.3 裁决顺序状态图（验收硬门；v1.1 统一为三段式）

**裁决优先级（高 → 低）：熔断硬上限 > 组合级裁决 > 单腿级裁决。**

1. **第一段·熔断硬上限**：任一熔断触发——单腿 ddc>20% **或** 组合回撤>15%——立即停，执行对应熔断动作。「熔断」不区分组合/单腿层级，**谁触发谁生效**；硬上限不可被任何层级覆盖、不可被反向指令抵消。
2. **第二段·组合级裁决**：无熔断时，组合级指令优先于单腿级。典型：组合加仓 vs 单腿减仓 → 按组合级执行（加仓），但进冷却期（§1.2⑦）。
3. **第三段·单腿级裁决**：组合级未表态的场景按单腿级执行；两级同向（都减仓）→ 取更保守（减更多）。

| 情形 | 裁决结果（v1.1 统一口径） |
|---|---|
| 同向（都减仓） | 取更保守（减更多） |
| 反向（组合加 / 单腿减，无熔断） | 组合级优先（加，但进冷却期） |
| **单腿熔断（ddc>20%）** | **熔断硬上限立即生效（执行熔断动作），组合级不得覆盖** |
| **组合熔断（回撤>15%）** | **熔断硬上限立即生效，单腿级不得覆盖** |
| 双熔断同时触发 | 任一熔断即停；动作取更严者 |

> **v1.1 修订说明**：v1.0 表中第 3 行（单腿级优先）与第 4 行（组合级优先）层级口径不自洽；现统一为上述三段式——熔断升为最高优先级硬上限，不再区分触发层级。§1.1 总图、§1.2⑦、§4.4 同步更新，全文以本节为裁决顺序唯一出处。

### 7.5.4 危机相关性跃迁监控（P1，低成本高性价比）

- **0.75 = 入池筛查阈值**（平时测，衔接 G-S5 与 R-335 两腿相关性上限）。
- **运行时监控**：滚动 20 日持仓相关性，任意两腿 > 0.85 且呈上升趋势 → 自动触发防御性降仓（即使未到 15% 熔断线）。
- 与 §7.1 RET-4 衔接：0.85 上升趋势 = 先发防御动作；0.90 = 提级审查。分级动作不等熔断。
- **与 §4.4 交叉引用（v1.1）**：本条运行时相关性监控已正式并入 §4.4 组合级风险闸门表（层级 = 组合级）；定义以本节为唯一出处，§4.4 只引用不重复定义。

## 10. 结论与建议

1. **破的边界清晰**：破=私有术语体系、隐式可变 JSON 状态机、未量化的组合/晋升门禁、打补丁式回测脚本、无退役机制；**不破**=组合作为一等版本对象、一切变更走同一条流水线、成绩单=回测成绩+逐条门禁原因、三方对账、双层门禁职责划分、单机零常驻约束。"治理骨架机构级值得坚持"（评审）与"破而后立"（用户）不矛盾——破的是落地层个人历史包袱，立的是同一治理思想的机构标准表达。
2. **目标架构**：七层标准分层（数据→因子→回测→组合构建→组合→执行→风控，横切 Iteration Ledger），全标准术语；新增组合构建层=可插拔求解器（等波动率→风险预算/ERC，明确不用 MVO），配置与求解分离。
