## 1. 系统全景：五层流程（从无到有）

```
L0 数据层     采数：K线/财务/指数/估值 → 校验报告
   ↓ 原料
L1 因子层     72因子字典 + IC/ICIR检验 + 因子观察池
   ↓ 武器
L2 选股层     股息+ROE+ROA小盘策略（V2_d25_n30_p10）+ 三重gate + WF
   ↓ 买什么
L3 择时层     trendvol × 估值信号 i4_q3z（年化15.01% / 2015段-28.29%）
   ↓ 什么时候买多少
L4 模拟盘     paper_engine 日度/调仓/校验 3条cron + 影子并行 + 劣化检测
   ↓ 实弹演习
L5 进化闭环   evolution_engine LLM因子进化 + review→pending→confirm
              （唯一仍靠人工串的层）
```

### 1.1 各层现状盘点

| 层 | 关键资产 | 自动化程度 | 缺口 |
|---|---|---|---|
| L0 数据 | data/（K线101万条/财务/估值PE 2005-2026） | 采集脚本手动触发；validate cron每周日 | 估值数据周更（task-0272在补） |
| L1 因子 | factor_catalog.json（72因子9分类） | IC检验脚本手动跑 | 无自动迭代 |
| L2 选股 | model/main.json + 26个candidates + history.jsonl | 三重gate+WF已代码化 | 触发靠人工派任务 |
| L3 择时 | i4_q3z 系数0~1，月末信号次月生效 | 回测代码化；正在固化 | 数据链路补齐中 |
| L4 模拟盘 | 3条cron + switch_log + 劣化检测 | **全自动运行** | — |
| L5 进化 | evolution_engine + factor_pool | 引擎存在 | **无定时、无统一runner、无想法入口** |

### 1.2 关键机制（已具备）

- **模型版本管理**：main.json（生效）→ pending.json（待确认）→ sota.json（历史最优）→ switch_log.jsonl（切换留痕）
- **升级门槛**：三重gate（年化≥主模型×0.9 / 回撤夏普组合 / Calmar）+ walk-forward三窗OOS + 影子并行对比 + **人工confirm**（task-0254改造后默认不直接merge）
- **劣化检测**：check-degradation 滚动60日年化/回撤超标→建议回退
- **因子观察池**：被拒候选中IC≥0.025的有效因子入池复用

## 2. 量化Tab四模块定位审视

### 2.1 现状结构（task-0270 后）

| 子Tab | 内容 | 对应层 | 定位 |
|---|---|---|---|
| 数据·因子 | 数据健康 + 因子库 + IC趋势/年度 | L0+L1 | **弹药库**：原料质量+武器清单 |
| 模型 | 选股模型(Alpha) + 择时模型(仓位层) + 系数月度 + 进化历史 | L2+L3+L5 | **作战方案**：当前生效什么 |
| 回测·生命周期 | 端到端指标 + 无择时对照 + 分年度 + 危机段 + WF + 报告库 | L2×L3验证 | **历史战绩**：方案行不行 |
| 模拟实盘 | 净值 + 持仓 + 交易 + 运行版本 + 策略参数 | L4 | **实弹演习**：真刀真枪跑 |

四模块 = 「弹药→方案→战绩→演习」闭环，定位合理，不需要推翻。

### 2.2 缺口：控制面缺失（对照目标体验）

用户心智模型：**「我只提想法，系统自动跑完全程，我随时可回退」**

现状四个「没有」：
1. **没有想法入口**——因子idea无处登记、追踪、消化闭环，页面无「想法池」
2. **没有过程可视**——L5进化是发动机，但页面上只是历史列表，无运行状态、无pending确认操作
3. **没有时间线**——113份报告散在results/，无append-only决策日志，人工回退要考古switch_log.jsonl
4. **没有控制按钮**——确认合并/回退只能靠派任务执行，页面看得到按不了

## 3. 目标体验（北极星）

> 无名只在三个时刻出现：
> ① **产生想法**：「帮我试一下股权风险溢价因子」
> ② **收到通知**：微信收到摘要「v1.2候选：年化+2.1%，WF三窗全正，详情见Dashboard」
> ③ **做出决策**：Dashboard上点「确认生效」或「放弃」，或任何时候点「回退到v1.1」
> 其余全部自动。

## 4. 自动化管道设计

### 4.1 管道总览

```
[想法池 ideas/pool.jsonl]──┐
                           ├→ 半月度cron: evolution_pipeline.py --cycle
[LLM因子引擎（补位）]──────┘      ① 数据校验（fail-fast）
                                  ② 迭代生成（想法优先消化 → LLM进化补位）
                                  ③ 版本化回测 + WF样本外
                                  ④ 三重gate评估
                                  ⑤ PASS → pending + 影子并行启动
                                  ⑥ 微信通知摘要（含报告链接）
                                  ⑦ 人工Dashboard确认 → confirm → main切换+switch_log
                                  ⑧ 劣化巡检cron → 超标告警 + 一键回退建议
```

### 4.2 P0 决策日志（一切的基础）

- `model/decision-log.jsonl` append-only，schema：
```json
{"ts":"...","layer":"L2/L3/L5","trigger":"idea|cron|manual","action":"backtest|evaluate|merge|rollback",
 "from_ver":"v1.1","to_ver":"v1.2","metrics":{...},"report_id":"iteration-20260815","outcome":"merged|pending|rejected|rolled-back"}
```
- 每次回测/评估/切换/回退自动追加
- Dashboard「时间线」直接读此文件 → 回退 = 找最近一条merged记录一键恢复

### 4.3 P1 想法池

- `ideas/pool.jsonl`：`{id, ts, text, status: open→digesting→tested→adopted|archived|untestable, test_result_ref}`
- 入口：微信发小朱桑一句话即登记；Dashboard可看状态
- 每轮runner优先消化open想法：想法→结构化因子假设→回测→结果回写
- 消化失败不阻塞：status=untestable + 原因

### 4.4 P2 统一runner（半月度cron，HP）

- `scripts/evolution_pipeline.py --cycle` 单命令串全链，任一步失败fail-fast并通知
- 产出统一报告 `results/iteration-YYYYMMDD/report.md`：本轮想法消化情况+新因子+回测对比+gate结论+建议
- **只做编排不重写**，兼容现有 evolution_engine / evolution_review / model_manager

### 4.5 P3 页面改造（Dashboard量化Tab控制面）

- 模型页顶部「当前生效」卡：主模型版本+择时版本+近30日表现+最近决策
- 新增「决策时间线」段：decision-log渲染，每条带报告链接
- pending卡片：指标摘要 + 「确认生效/放弃」按钮
- 回退按钮：时间线每条merged记录旁「回退到此版」（带确认弹窗防误触）
- 想法池卡片：状态列表

- API：`/api/quant/decisions`、`/api/quant/pending`、`/api/quant/ideas`
- 操作：`POST /api/quant/pending/confirm|reject`、`POST /api/quant/rollback`（经sync回传HP执行）

## 6. 风险与边界

| 风险 | 对策 |
|---|---|
| 想法无法结构化（太模糊） | status=untestable+原因，不阻塞其他想法 |
| LLM进化质量不稳 | 三重gate+WF挡住，最坏pending被拒，不影响主模型 |
| 回退误触 | 确认弹窗 + 操作写decision-log留痕 |
| HP/VPS分离 | runner在HP跑，decision-log随auto_sync每30分钟回传，页面读VPS副本 |
| 半月度频率 vs 数据新鲜度 | runner第一步数据校验fail-fast，数据不新鲜自动跳过本轮并通知 |

## 7. 结论

- 五层架构已基本成型，L4模拟盘已全自动，**唯一断点是L5进化闭环的「定时+统一编排」和控制面**
- 改造不推翻任何现有模块，纯增量：+决策日志、+想法池、+统一runner、+页面控制面
- 人工决策点收敛为一个：pending确认（合并/放弃），其余全自动，回退任意版本一键完成
