## 2. 数据契约 v2（crowding-indicators.json 规范）

设计原则：**快照与历史分离**（JSON=当期快照+短窗口；CSV=全史）、**新鲜度三字段**（生成/数据/截止分层）、**向后兼容**（新增字段全部可选，M4.7 API 不改也能跑）。

```json
{
  "schema_version": 2,
  "generated_at": "2026-08-17 16:16:10",
  "generated_by": "cron|manual",
  "latest_date": "2026-08-14",
  "data_cutoff": {
    "parquet_max_date": "2026-08-14",
    "refresh_cadence": "weekly_sun_2000",
    "stale": false
  },
  "overall_flag": "red",
  "data_source": "本地 data/all_stocks_qfq/*_daily_qfq.parquet + hs300/zz500；akshare 不可达故全本地自算",
  "microcap_definition": "每日全市场按总市值(收盘×总股本)排序后20%",
  "indicators": {
    "micro_turnover_share": {
      "name": "微盘成交占比(20日均)", "key": "micro_turnover_share_roll20",
      "latest": 0.0271, "pct_rank_60d": 6.7, "flag": "green",
      "thresholds": {"yellow": null, "red": null, "note": "分位型指标"},
      "series_90d": [["2026-04-24", 0.031], "…共90个[date,float]，新增，供看板sparkline"],
      "note": "微盘成交额/全A成交额"
    },
    "micro_turnover_pctile":  { "name": "…", "latest": 6.67, "pct_rank_60d": null, "flag": "green", "thresholds": {"yellow": "P90", "red": "P95"}, "series_90d": [] },
    "excess_decay":           { "name": "小盘超额衰减60d斜率", "latest": -0.0028, "tstat": -6.99, "pct_rank_hist": 5.5, "flag": "red", "series_90d": [] },
    "snowball_knockin":       { "name": "雪球敲入距离(zz500代理)", "latest": 0.585, "latest_date": "2026-08-14", "flag": "green", "proxy": "zz500", "series_90d": [] }
  },
  "capacity": { "summary": { "method": "ADV20×参与率÷权重, 11票瓶颈min", "conservative_5pct": 13374817, "neutral_10pct": 26749634, "optimistic_15pct": 40124451, "bottleneck_stock": "603551" }, "per_stock": ["11项，同现状"] },
  "microcap_eqw_index": ["保留但建议截尾：只留近3年(约730点)，全史迁移到 crowding_history.csv 新列；阶段B API 继续剔除"]
}
```

契约要点：
1. `schema_version`（必填）：M4.7 API 读到 ≥2 才启用新字段渲染，否则走旧路径。
2. 新鲜度三层：`generated_at`（管线心跳）≠ `latest_date`（指标日期）≠ `data_cutoff.parquet_max_date`（原料截止）。**看板 stale 判定改为 `latest_date` 距今 >10 个交易日**，取代纯 mtime 的 192h（消除周末/节假日误报，同时保留 mtime 兜底）。
3. `series_90d`（可选）：每指标带 90 日短序列，看板 sparkline 数据源，替代"全史嵌 JSON"。
4. `microcap_eqw_index` 截尾到近 3 年：93KB → 约 35KB；全史唯一权威载体=crowding_history.csv（补 `micro_eqw_index` 列）。
5. flag 语义冻结：green/yellow/red/unavailable 四值，与 M4.7 现有渲染兼容。
6. history CSV 列名不变（8 列），只增列不删列。

## 3. 管线设计（不改 HP crontab 的增量方案）

```
┌────────────────────── HP（quant-evolve）──────────────────────┐
│  周日 07:00  collect_crowding.py（现有cron，不动）              │
│      ↓ 读 parquet(截至上周五) → 四指标+容量+全史CSV             │
│      ↓ 产出 v2 契约 JSON（schema_version=2 + series_90d）      │
│  周日 20:00  refresh_data.py（现有cron，不动；数据自洽周一）    │
│                                                                │
│  【增量·另立项】方案I：HP 侧 collect_crowding.py --append 模式  │
│    周一~周五 16:50（在 risk_patrol 16:45 之后新增一行cron）     │
│    复用增量 parquet → 只重算当行 → append CSV + 覆写 JSON 快照  │
│    前提：确认 data/ 每日增量到位（当前 refresh 仅周日，故先做    │
│    方案II：VPS 侧触发）                                        │
└──────────────┬─────────────────────────────────────────────────┘
               │ rsync（auto_sync_notify.py 每30min，已含 crowding JSON）
               │ 【增量】MIRROR_INCLUDES 追加 crowding_history.csv
┌──────────────▼────────── VPS ─────────────────────────────────┐
│  workspace-quant/results/crowding-indicators.json（看板读路径）│
│  workspace-quant/results/crowding_history.csv（阶段B 新增）    │
│      ↓ server.js /api/quant/crowding（阶段B 升级，见 §4）       │
│  【方案II·推荐先行】VPS 心跳侧加 freshness 校验任务（不动 HP）： │
│    每日检查 latest_date 滞后 >10 交易日 or JSON mtime >8d       │
│    → 写 notifications-queue → 微信提醒（复用现有通知链路）      │
└────────────────────────────────────────────────────────────────┘
```

决策建议：
- **先做方案II**（VPS 侧新鲜度告警）：零侵入、解决最疼的"静默失败"；改 workspace-quant/scripts 一个 VPS 脚本+VPS crontab（属 VPS 侧，非 HP crontab）。
- **方案I 后置**：采集频率提升的前提是数据频率提升（parquet 周更→日更需改 refresh_data 或接 VPS akshare 通道），涉及 HP 侧改动，按纪律**另立项**（建议命名：拥挤度日更管线 task，含 HP cron 增量行审批）。
- 周频本身与调仓节奏（月频）匹配：excess_decay 60 日窗口对 2 日滞后不敏感，**不建议为日更而日更**。

## 4. 阶段B 展示设计（server.js API + 前端卡片，390×844 无横向滚动）

### API 改造（`/api/quant/crowding`）
- 读到 `schema_version>=2`：透传 `series_90d`、`data_cutoff`、`generated_by`、各指标 `thresholds`；`microcap_eqw_index` 继续剔除（截尾后体积可控，但移动端不需要）。
- 新增计算字段 `freshness`：`{latest_date_age_trading_days, stale: bool, generated_age_hours}`，前端红点直接用。
- 兼容：v1 JSON（无 schema_version）→ API 照旧输出 + `freshness.stale` 用 mtime>192h 近似。

### 前端卡片（renderCrowdingCard 升级，不改布局骨架）
```
┌ 微盘拥挤度 ────────── ●red ─┐   ← 标题行：整体旗色圆点(现有)
│ 截至 08-14 · 生成 08-17 16:16│   ← 副行：freshness 徽标(stale 时黄条"数据滞后Nd")
│ 成交占比   2.71%  ▂▃▂▁▁ green │   ← 每指标一行：名称/当前值/90日sparkline/旗点
│ 换手分位   6.7    ▂▂▁▁▁ green │      sparkline=inline SVG, width:100%, 高28px
│ 超额衰减  -0.28%/d ▄▅█▇▆ red │      无横滚：行内 flex，数值列定宽
│ 雪球距离  +58.5%  ▁▁▂▂▂ green│
│ 容量 1.3/2.7/4.0亿(瓶颈603551)│   ← 现有三档行，保持
└──────────────────────────────┘
```
- 布局规则：卡片 `width:100%`、padding 12px；sparkline 用 viewBox 自适应（`preserveAspectRatio="none"`），杜绝固定像素宽；指标值保留现有 4 位内格式化；**不引入表格**（现有卡片已是 div 行式，维持）。
- `available:false` 占位文案不变；新增 `stale=true` 时卡片顶部黄色提示条（复用 riskStatus 卡的提示样式类）。
- 桌面 1440 与移动 390 共用同一卡片组件（现有 quant 卡已是响应式栈叠，无额外媒体查询）。

### 阶段B 验收口径（预写）
1. `node --check server.js` 通过 + 服务重启后 `/api/quant/crowding` 返回 `freshness` 字段。
2. 390×844 截图：无横向滚动条、四 sparkline 渲染、stale 提示条在人为改旧 mtime 时出现。
3. v1 旧 JSON 回滚兼容：临时换回无 schema_version 文件，卡片不报错。
