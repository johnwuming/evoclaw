# 跨引擎影子可视化 · 使用说明

> 范围：agent-dashboard 看板「模拟实盘·灰度」页底部「跨引擎影子（cross-engine shadow）」卡
> 实现：task-0464（影子落地）/ task-0465（首版卡片）/ task-0468（泛化·数据驱动）/ task-0469（A 在役线修复）
> 数据源：`workspace-quant/results/engines.json` + `results/engines/<id>/shadow_nav.csv`（或兼容平铺 shadow_nav.csv）

---

## 一、在哪里看

打开 **Agent Dashboard → 量化页 → 「模拟实盘·灰度」Tab**，滚动到页面**最底部**，即「跨引擎影子（cross-engine shadow）」卡片。

> 注意：不在「回测·生命周期」页。回测页的版本下拉列的是 registry 候选版本（如 a12_s2_reb），与影子是两回事。

## 二、卡片上能看到什么

卡片由三部分组成：

### 1. 引擎徽标行（所有引擎）
| 徽标 | 含义 |
|---|---|
| `A` ✅ 在役 | 真金在役引擎（当前=微盘选股 a13） |
| `A2` 👁 影子 | 影子观察中的引擎 |
| `clean 待启动（需 3-6 期）` | 影子期 clean_evals 进度（0=刚起步） |

### 2. 每引擎一张影子卡（当前只有 A2）
- 引擎标识：`影 A2 · <名称> · parent=A · 自 2026-08-23 · clean 待启动 · source=flat`
- **双线图**：
  - 蓝色 = **A 在役 NAV**（2006-2024 全史，取自 active/curves full，月度化）
  - 橙色 = **A2 影子 NAV**（月频，2006-2024 基线段）
- 两条线同一时间轴并排，可直接对比"有/无该影子臂"的历史净值差异。

### 3. 空态/占位（非错误）
- 「暂无影子引擎」= engines.json 无 shadow.mode=cross_engine 条目，属正常。
- 「影子 NAV 待同步」= 该引擎 shadow_nav.csv 未就绪。

## 三、怎么理解这张卡

- **A2 不是第二个独立选股引擎**，它是 A 的防御叠加臂（`type=sub_engine_overlay, parent=A`）：拥挤度高时对 A 组合降权（w=0.5），属于**层1 引擎内部**机制，**不是层2 中央风控**。
- 影子期语义：A2 在历史数据上回测达标（R-282 评审），现在进入 **3-6 个月影子观察**——用真实月度数据验证两腿（A 在役 vs A+A2 叠加）的跟踪与换手成本，期间**不参与真金交易**。
- `clean 待启动（需 3-6 期）`：影子期从 2026-08-23 起算，月度 evaluate 每月跑一次，每完成一个"干净"月份进度 +1；达到 3-6 期后进入人工裁决（真金分配=用户拍板，永不自动）。
- **低拥挤期 A2≈A 属预期**：T4 拥挤度臂在拥挤度低（p<40）时行为上等价于在役，两线几乎重合不是故障（R-273 判读规则）。

## 四、新增引擎如何接入（零代码）

任何新引擎（如未来的 B/C）加入影子，只需两步，**不需要改任何代码**：

1. **登记 engines.json**（真源 HP `~/quant-evolve/model/registry/engines.json`，同步到 VPS 镜像）：
   ```json
   {
     "engine_id": "B",
     "name": "引擎B名称",
     "status": "shadow",
     "type": "engine",              // 或 sub_engine_overlay
     "parent": "A",                 // 对比的在役引擎（无则 null）
     "layer1": { "nav_source": { ... } },
     "shadow": {
       "mode": "cross_engine",
       "since": "2026-09-01",
       "nav_path": "results/engines/b/shadow_nav.csv",
       "required_clean_evals": { "min": 3, "max": 6 }
     }
   }
   ```
2. **落影子 NAV 文件**：把该引擎的月度 NAV 写到 `results/engines/<id>/shadow_nav.csv`（列：`month,nav,ret`）。

完成后看板自动：
- 徽标行新增 `B 👁 影子`
- 自动渲染 B 的影子卡（B 影子 NAV vs parent 在役 NAV 双线）
- 每引擎独立 clean 进度

## 五、数据契约（给运维/开发）

| 项 | 规格 |
|---|---|
| engines.json 位置 | HP `~/quant-evolve/model/registry/engines.json` → 同步 → VPS `workspace-quant/results/engines.json` |
| 影子 NAV 文件 | `results/engines/<engine_id>/shadow_nav.csv`（列 month,nav,ret） |
| 兼容平铺 | 当前 VPS 只有平铺 `workspace-quant/results/shadow_nav.csv`；读取优先按 nav_path 映射，缺失回退平铺，响应标注 `source`（nav_path/flat/none） |
| 端点 | `GET /api/quant/engines`（清单）· `GET /api/quant/engines/:id/shadow-nav`（该引擎影子 NAV）· 旧 `/api/quant/engines/shadow-nav`（兼容别名） |
| parent 在役线 | 用 `GET /api/quant/active/curves` 的 strategy.full（全史）月度化；parent 非在役时降级 navPoints 兜底 |

## 六、常见问题

- **Q：A 在役线还是看不到？** 刷新页面（Ctrl+F5 清缓存）。若仍无，检查 `/api/quant/active/curves` 是否返回 strategy.full（应 2006-2024，约 1000 点）。
- **Q：两张卡的曲线几乎重合？** 低拥挤期属预期（见 §三），不是 bug。
- **Q：source=flat 是什么意思？** 表示当前读的是兼容平铺文件（`results/shadow_nav.csv`），而非按 nav_path 的子目录文件；数据内容一致，仅路径不同。
- **Q：clean 进度一直 0？** 影子期 2026-08-23 刚起步，月度 evaluate 尚未产生第一个月度点，0 是正确起点。
