# 外部 AI 补充建议：组合构建层 Portfolio Construction Layer（用户提供，2026-08-27 23:39）

用户追问："从低频量化模型实操角度，整个 vC-x.y 组合版本还会缺少什么吗？怎么补充，比如我要叠加更多的模型通过风控分仓位"

## 核心结论
缺的不是几个字段，而是一个全新的层——「组合构建层 Portfolio Construction Layer」。
vC-x.y 管的是「组合内容版本化」（装了哪条 A 腿、哪条 gold 腿、什么风控参数）；「叠加更多模型+按风控分仓位」是另一个问题：给定风险预算下，多个模型的权重和仓位怎么"算出来"。这是组合构建层+风控中枢的事，与 vC 是上下游关系。若只给 vC 加个 model_weights 字段，会把「配置」和「求解」耦合，很快失控。

## 三个关键设计点
1. **权重求解器可插拔、按阶段演进**：低频多模型场景从 等波动率 → 风险预算（Risk Budget/ERC）过渡即可，别一上来 MVO（对收益预测误差极敏感，容易过拟合集中）。
2. **相关性才是风险**：多个模型若底层同源（如都做多科技股趋势），相关性>0.75，危机时趋近 1，分散失效。要用**持仓相关性**（不只是净值相关性）做决策。
3. **再平衡"打架"问题**：策略 A 因波动率飙升自动减仓 → 其风险贡献 RC_A 骤降 → 组合级再平衡器反向"加仓 A" → 反复横跳耗成本放大风险。解决：策略内部重大调整时通知组合引擎进**冷却期**，并明确"组合级 > 策略级"为唯一裁决者。

## 落地优先级
- P0（保命）：组合构建器 + 波动率目标化 + 回撤分级闸门（<5% 正常 / 5-10% 提级 / 10-15% 降仓×0.5 / >15% 熔断）
- P1（真正分散）：相关性筛查 + 风险预算/ERC + Ledoit-Wolf 协方差
- P2：约束体系 + 分层风险预算 + 退役机制
- P3：HRP、体制切换等（可选）

## 重申硬约束
门禁阈值必须量化成数字；回测引擎必须先做正确性审计。
